# VeyaTV 最新平台竞争力与体验分析

> 分析日期：2026-11-08  
> 分析对象：本地最新版 `bcf49d8`  
> 部署状态：该提交尚未部署到 `origin/main`，本文所述新能力属于本地最新版，不是当前线上版本。  
> 分析范围：工作台、创作方法与 Skill、Agent、生产画布、自由画布、视觉层级和竞品差异。  
> 本文只做产品与体验分析，不包含代码改动。

## 一、核心结论

最新版已经明显从“AI 剧本工具”升级为“短剧连续生产系统”，但它还没有把这种能力转化成人人都能立刻感知的首屏价值。

一句话概括：

> 现在的 VeyaTV 更像一个正在成形的短剧生产操作系统，但还不像 Flova 那样能让用户马上看到“我说一句，它已经做出来了”。

因此，接下来的重点不应继续增加模块；重点应放在打通**首次价值闭环**，同时放大真正属于 VeyaTV 的差异化：跨集一致性、生产门禁、非破坏式扩集、影响分析和成本控制。

## 二、最新版解决了什么

这次优化是有效的，平台已经越过了几个关键门槛：

- 工作台不再只是项目列表，而开始展示生产阶段、阻断、下一步和工作脉搏。
- 样片、小批、整季三种生产模式已经形成真实的生产路径。
- 扩集是非破坏式的，只补缺失集，不覆盖已有集，这很有价值。
- 生产画布与自由画布并存，产品定位比之前清楚。
- Agent 已经能识别快速出片、改编、继续制作、生产检查、自由编排等意图。

尤其是“样片验证 → 小批生产 → 整季生产”，这已经不只是普通生成工具，而是短剧行业的实际生产逻辑。

## 三、三个工作面

| 工作面 | 当前水平 | 用户现在能完成什么 | 核心缺口 |
|---|---|---|---|
| 工作台 | 已基本成立 | 从想法、小说或示例开始；查看阶段、阻断、下一步；启动样片、小批或整季 | 空项目仍被项目级导航包裹；用户要先理解六步，才能看到第一个成果 |
| 创作与 Skill | 有潜力但未闭环 | 分步编辑人物、大纲、分集、定妆、场次、分镜；选择 Agent 意图 | “快速出片”目前主要停留在意图标签，没有真正执行生成、预算和结果回写 |
| 画布 | 更像生产总览 | 查看人物、分集、场次、镜头、图片、视频和阻断 | 节点主要用于展示状态，还不能直接处理阻断、批量返修、预览变更影响和推进生产 |

所以，工作台已经比较接近合格的生产驾驶舱；创作 Skill 是最有差异化、但最需要补闭环的部分；画布则还没有完全成为用户每天真正会操作的生产工具。

## 四、与竞品的真实差距

- **对 Flova**：它最直接的优势是极短路径和即时结果。用户的预期是“一句想法 → Agent 自动完成 → 得到可编辑的视频、音频和人物”。VeyaTV 目前在这条路径上仍会进入项目结构。
- **对即梦、可灵等模型产品**：它们更强的是一手模型效果、生成参数和视觉结果。VeyaTV 不应在“单条视频生成质量”层面硬碰，而应竞争成片连续性、返修效率和生产成本。
- **对 LibTV 一类画布产品**：它们更强调创意画布和可见资产。VeyaTV 的画布应服务于短剧生产管理，不能退回成通用节点编辑器。

真正的竞争位置应该是：

> Flova 帮你更快生成内容，VeyaTV 帮你把一部多集短剧稳定做完，并控制返工与成本。

这个优势目前在产品里存在，但还不够显眼。

## 五、最影响用户收益的问题

### 1. 第一次使用的价值来得太晚

用户说“从一句想法开始”，实际进入的是核心人物。平台先解释六步，而不是先给一个短样片、一个镜头测试或一份生产判断。

对新用户最有说服力的不是流程图，而是：

> 我的一句话已经变成了什么，需要花多少钱，还要做几次确认。

### 2. “快速出片”承诺大于当前能力

这是目前最明显的体验缺口。用户选择快速出片后，还没有真正的快速视频 Composer、生成预算、任务状态和结果回写。

如果这里是空的，平台就会同时失去 Flova 的低门槛和六步工作流的可信度。

### 3. 存在三套进度语言

生产阶段有“来源、人物、大纲、分集、定妆、场次、分镜、交付”，左侧又是六步，工作台同时还有阶段和阻断信息。

每种表达单独看都合理，放在一起用户会问：现在到底在哪个阶段，真正卡住我的是哪一项？

### 4. 生产画布还不能解决阻断

用户看到某个镜头缺图、某集缺视频以后，下一步应该是：

- 直接补生成
- 批量重做
- 查看改动会影响哪些下游内容
- 查看预计成本和时间

如果画布只能看不能处理，它最终会变成一块昂贵的监控屏。

### 5. 视觉上仍然存在持续消耗

实际截图在 1440、768、390 三个宽度都没有横向溢出，移动端单列结构也成立。但自动审计仍显示约 63% 到 71% 的文字小于 13px，顶部公告占据明显正文空间，同时存在较多发丝线面板和微小标签。

这不是简单的“颜色不好看”，而是：

- 信息层级过于接近
- 说明文字太多、结果和素材太少
- 用户长时间扫描会疲劳

尤其首屏目前仍然“看起来像介绍产品”，而不是“已经开始生产”。

## 六、用户收益最大的五件事

### P0：一句话快速验证

新增真正的快速入口：

```text
一句想法
→ AI 自动整理创作 Brief
→ 只让用户确认题材、3 秒钩子、制作范围
→ 显示预计时长与成本
→ 生成 30～90 秒样片或第 1 集
→ 结果进入同一项目台账
```

这不是简单复制 Flova，而是一个低成本获客入口。用户验证结果以后，可以继续进入六步精修。快速模式和分步模式必须共享同一份项目事实，不能形成两套系统。

### P0：统一首次进入

建议首次使用只保留两个选择：

- 快速试片：先看到结果
- 分步制作：需要控制人物、剧本和镜头

用户选择前不展示完整六步详情。空项目阶段也不应显示“未命名项目”和项目级六步菜单，否则用户会误以为自己已经进入了一个项目。

### P0：让 Agent 从标签变成执行计划

现在意图识别已经有基础，下一步需要让 Agent 输出：

- 准备调用哪些 Skill
- 会影响哪些项目事实
- 预计消耗多少额度
- 哪些操作需要用户确认
- 执行后回写到哪个版本

第一阶段不需要完全自动化，但至少要让用户看到“Agent 准备怎么做”，然后允许确认执行。

### P1：统一生产阶段和六步

建议形成唯一关系：

- 六步是“内容生产方法”
- 生产阶段是“当前项目状态”
- 阻断是“现在必须处理的事情”

不要让三套内容同时争夺主视觉。用户只需要知道：现在在哪、卡在哪、下一步点哪里。

### P1：把生产画布改成可操作的生产网络

画布最有价值的不是拖节点，而是展示：

- 人物影响哪些集和镜头
- 修改这个人物会波及哪些定妆图、分镜和视频
- 哪个镜头的返工成本最高
- 哪些资产可以批量重生成
- 当前阻塞会造成多少预计成本和时间损失

这会是 VeyaTV 比 Flova 更有分量的差异化。

## 七、建议顺序

1. 先完成一句话快速试片，并让结果回到项目台账。
2. 重做空项目首次入口，去除项目级六步干扰。
3. 让 Agent 意图输出可执行计划和成本预览。
4. 统一阶段、六步、阻断三者关系。
5. 让生产画布支持处理阻断、批量返修和变更影响预览。
6. 最后再处理公告位置、微标签、字号和发丝线等视觉问题。

视觉优化当然需要做，但它不是当前最影响用户是否愿意继续用的因素。现在最大的收益来自：**让用户在五分钟内看到第一个可判断的结果，并知道这次验证花了多少钱、下一步能得到什么。**

### 建议执行顺序

1. 完成 10 集真实生产链验收。
2. 统一快速入口，并给出一次确认即可理解的总预算和费用边界。
3. 补浏览器全链路 E2E，固定生成、返修、视频、时间线与导出主路径。
4. 接入产品漏斗指标，至少覆盖首次结果耗时、试片转化、断点恢复、返修和整季完成。
5. 统一进度 DTO，消除六步、生产阶段和阻断的三套口径。
6. 继续推进 Agent 执行闭环、外部视频回传、本地图库恢复和全站视觉密度。
7. 最后扩展跨供应商视频模型、自动路由和视频多参考图。
