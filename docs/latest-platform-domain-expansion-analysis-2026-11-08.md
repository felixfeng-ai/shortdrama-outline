# VeyaTV 创作品类扩展分析：营销、电商与其他方向

> 分析日期：2026-11-08
>
> 分析范围：当前创作与生产架构、营销视频、电商视频、品牌片、教育视频及其他内容品类。
> 本文只做产品、业务和技术边界分析，不包含代码改动。

## 一、核心结论

可以拓展，但不建议现在把“营销、电商、教育、品牌视频”作为并列核心业务同时铺开。

更合理的路线是：

> 先把短剧做成可验证的生产系统，再把“营销视频”作为第一个相邻品类；电商先作为营销视频的专用模板验证，而不是立即独立成完整业务线。

## 二、当前基础

代码里其实已经预留了扩展空间：

- `ProjectType` 已包含 `quick_video`、`drama`、`marketing`。
- Agent 已能识别营销、广告、投放、小红书、商品视频、转化等意图。
- UI 目前只开放快速出片和短剧生产，营销视频标记为“后续开放”。
- 所有 Skill 分类仍以小说改编、短剧开发、视觉一致性、分镜和交付为主。

所以并不是完全不能扩展，而是当前生产事实仍然明显围绕“集数、人物、分集、场次、镜头”建立起来。

## 三、必要性判断

| 方向 | 必要性 | 判断 |
|---|---|---|
| 营销视频 | 高 | 与现有能力最接近，可复用人物、视觉资产、分镜、配音、视频和平台导出 |
| 电商商品视频 | 中高，但条件成立再做 | 商业价值高，但涉及商品、SKU、卖点、功效声明、平台规则和批量变体 |
| 品牌形象片 | 中 | 可以复用生产能力，但客户频次和交付标准差异较大 |
| 教育课程视频 | 中低 | 更需要课件、知识点和讲师体系，不是当前最短路径 |
| 通用社交媒体内容 | 低 | 容易进入模板工具竞争，无法发挥多集一致性、Canon 和生产门禁优势 |

营销视频的必要性最高，因为它不需要推翻现有平台，只需要把“创作目标”和“交付单位”换掉一部分。

## 四、为什么现在不能只加几个 Skill

如果只是增加“营销脚本”“商品文案”“广告生成”几个 Skill，最终会变成普通视频生成入口，用户仍然得不到稳定的广告变体。

真正的差异应该来自项目事实和门禁：

- 短剧关心人物一致、分集钩子、场次连续和整季交付。
- 营销关心目标受众、产品卖点、Offer、CTA、渠道、时长和 A/B 变体。
- 电商还多一层商品事实：SKU、价格、促销、功效限制、平台审核和素材授权。

当前生产模式的核心字段是 `targetEpisodes`，技能分类也是短剧流程。如果直接把营销项目套进现有模型，会产生“营销视频第 1 集”“营销项目需要补 30 集”这类不合理概念。

## 五、推荐架构

保持同一个工作台和画布，但让项目类型决定四套内容：

- 创作事实：短剧是人物与 Canon；营销是产品、受众、Offer 和品牌 Canon。
- 工作流：短剧是六步或多集生产；营销是 Brief、脚本、变体、审核和投放交付。
- 质量门禁：短剧检查人物一致和追看；营销检查 3 秒钩子、卖点、CTA、渠道规格和合规。
- 交付规格：短剧按集交付；营销按渠道、时长和变体组交付。

其中最关键的技术抽象是把“集数”扩展为统一的**交付单元**：

- 短剧：一部作品包含多集。
- 营销：一次 Campaign 包含多个广告变体。
- 电商：一个活动包含多个 SKU 或多个卖点视频。

这样生产计划、额度、任务、版本和画布才能跨品类复用，而不是复制三套系统。

## 六、建议顺序

1. 先完成当前短剧的快速验证和完整生产闭环。
2. 开放“营销视频”，但只做两个真实场景：产品推广和品牌故事。
3. 增加“变体工作区”：同一 Brief 生成多个钩子、脚本和画幅版本。
4. 接入小红书、抖音、视频号等渠道规格与交付预检。
5. 找到 2–3 个真实商家验证后，再把电商作为营销视频的专用项目模板。
6. 暂不进入教育、通用口播、企业宣传片等宽泛品类。

## 七、是否值得做

如果目标是扩大市场规模，营销视频值得做，而且比电商更早做。
如果目标是尽快证明平台价值，现阶段继续聚焦短剧收益更高。

建议设置一个明确门槛：至少拿到 3 个持续有月度视频需求、愿意为批量变体和交付效率付费的营销客户，再正式开放营销品类。否则只是增加菜单和 Skill，无法形成新的竞争壁垒。
