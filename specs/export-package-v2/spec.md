# 项目包 V2 与导入恢复

## 目标

把当前“能下载一些文件”的导出升级为可信的项目交接与备份能力。交付包保持轻量、适合交给导演或执行人员；完整备份保留全部版本、任务、候选图和本地偏好，能重新导入当前平台继续工作。

## 能力点

### R1 · 导出内容补齐项目完整状态

- `project.json` 使用真实项目名，不再从故事想法截取。
- 同时导出 `genre`、`brief`、`look`、`judgments`、`episodeCount` 和 `exportedAt`。
- 导出失败、缺失参考图和缺失生成图写入 `export-report.json`，不再静默跳过。
- README 只列出包内真实存在的文件。

### R2 · 两种明确模式

#### 交付包

- 包含最新文本产物、角色/地点/镜头执行文件、已采用生成图。
- 不包含历史候选、旧快照和完整任务历史。
- 适合发给导演、剪辑、出图执行人员。

#### 完整备份

- 包含全部快照版本、生成任务、已采用图与全部历史候选。
- 包含本地偏好和本地参考图。
- 可导入到新的项目继续编辑。

### R3 · 统一 Schema V2

- `chengju.project` 升至 `schemaVersion: 2`。
- 客户端 ZIP 与服务端 `/api/export` 使用相同顶层结构：项目、设置、故事、资产、引用、关键帧、任务、快照、文件清单、警告。
- 所有图片记录实际相对路径；文件名保留可读中文角色名、地点名、集号和镜号。
- 所有导出路径做非法字符清理、路径穿越防护和重名去重。
- `manifest.json` 提供文件清单；`project.json` 提供完整状态。

### R4 · 可读产物升级

- `prompts.csv` 增加地点、下一镜衔接、缺失参考、镜头实体 ID、已采用图路径。
- `storyboard/index.html` 增加视觉宪法、地点锚点、画幅/时长/状态、已采用图缩略图。
- 离线 HTML 只引用 ZIP 内相对图片，不引用网络资源。
- `production/chaining.txt` 始终存在；无衔接时写明原因。

### R5 · 导入恢复

- 项目菜单提供“导入项目包”，接受 V2 ZIP。
- ZIP 读取只信任应用导出的 store 模式；拒绝路径穿越、加密、未知 schema 和不合法字段。
- 导入创建新项目，不覆盖现有项目。
- 交付包恢复最新内容；完整备份恢复快照历史。
- 本地参考图进入本机图库，不上传服务器；生成图恢复到当前项目资产历史。
- 导入完成后切到新项目，并显示恢复数量与缺失警告。

## 验收场景

1. 项目标题含 `/`、角色名含中文时，ZIP 内路径仍合法且可读。
2. 一个角色有 3 张候选图，完整备份含 3 张；交付包只含已采用 1 张。
3. 某张生成图下载失败时，项目仍生成成功，但 `export-report.json` 有明确缺失记录。
4. `brief`、`look`、`judgments` 在导出后可重新导入恢复。
5. 完整备份导入后，快照版本数、任务、选中图和本地参考图都可用。
6. 恶意 ZIP 条目 `../secret` 被拒绝，不写入磁盘。
7. 分镜 HTML 可离线显示视觉宪法、地点锚点和已采用缩略图。

## 非目标

- 不导入 V1 包。
- 不恢复生成任务的远端 Provider 任务 id；恢复的是本地任务与资产历史。
- 不上传本地参考图像素到服务器。
