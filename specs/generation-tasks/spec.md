# 关键帧生成任务控制

> 用户已确认继续任务管理能力；图生视频仍放在最后。

## 1. 目标

让用户能停止当前关键帧生成请求，看到取消状态，并在失败后直接重试。任务状态必须与用户看到的按钮和结果一致。

## 2. 硬边界

- 停止等待后，不创建关键帧资产。
- 已提交给通义的任务不保证能被远端取消；界面必须说明“已停止等待”，不能承诺平台侧一定停止计费。
- 取消只影响当前请求和当前任务，不删除历史关键帧。
- 图生视频不进入本轮。

## 3. 场景

### T1 停止生成

**Scenario T1.1**
Given 用户正在生成角色定妆图或镜头首帧
When 用户点击“停止生成”
Then 前端中断请求，任务状态变为 `canceled`，不创建新资产。

**Scenario T1.2**
Given 请求已经中断
When 用户再次点击
Then 创建新任务并重新生成，不复用已取消任务。

### T2 失败重试

**Scenario T2.1**
Given 上次任务失败且当前没有采用关键帧
When 用户查看操作按钮
Then 按钮文案为“重试生成”，点击正常发起新请求。

### T3 状态一致性

**Scenario T3.1**
Given 任务已取消
When 用户刷新项目
Then 看到“已停止等待”，不会显示为成功或继续运行。

## 4. 验收

- 任务仓储、请求中断和 UI 状态均有测试。
- 取消、失败重试不覆盖历史资产。
- 全量测试、类型检查、生产构建和浏览器验收通过。
