# 首次创作入口与移动端工作区收口

## Goal

让没有项目的首次访问明确停留在创作入口，而不是伪装成已经进入项目工作区；同时保证模式切换在 React 完成 hydration 前也不会丢点击，并消除移动端固定导航遮挡核心操作的问题。

## Requirements

### R1 空项目不显示项目壳

- 没有项目时，侧栏只显示工作区级入口，不显示当前项目步骤和项目工具。
- 空项目总览不显示五项底部导航和 Veya Agent 工作舱。
- 用户完成快速创作或进入分步制作并产生项目后，项目级导航和 Agent 自动恢复。

### R2 模式切换必须有原生链接兜底

- 总览、创作、画布三个模式使用带真实 URL 的链接，而不是只能在 hydration 后响应的纯按钮。
- 链接在 hydration 前可直接导航到目标模式。
- hydration 完成后点击仍由客户端状态切换，不触发整页刷新。

### R3 移动端固定层不得遮挡主操作

- 有项目时，移动端底部导航保留。
- Agent 收起抓手必须位于底部导航上方，不能被导航覆盖。
- 工作区底部必须预留底部导航和 Agent 抓手的合计安全空间。

### R4 兼容现有视觉体系

- 不新增颜色、字体或圆角体系。
- 桌面端现有布局不变；改动只收口空项目状态、模式链接语义和移动端固定层。

## Acceptance

- 空项目桌面和手机截图中不再出现“未命名项目”步骤组、项目工具、底部导航或 Agent 收起行。
- 在 hydration 完成前点击“创作”仍会进入 `?view=create`。
- 有项目时三模式可自由切换，URL 与视觉状态一致。
- 390px 下 Agent 抓手与底部导航不相交，最后一个主要操作可以滚动到导航上方。
- 相关单测、全量测试、类型检查和生产构建通过。
