# 原生 App · 真实 Agent 工具循环

## 1. 目标

把移动端 Agent 从固定本地提案升级为真实服务端工具循环：读取当前账号有权限的项目快照，调用现有 Agent 工具，返回回答、工具轨迹和待确认建议。

本轮不直接修改镜头、不触发生成任务、不写快照。用户点击建议只表示保留/查看，不代表已经写入项目。

## 2. 硬边界

- 只允许当前会话 owner 的项目。
- 用户输入 2–300 字，服务端再次校验。
- 单轮最多 3 次模型调用，每次调用沿用现有 Agent 额度权重。
- 工具集合固定为现有只读工具和 `propose_*`，不接受客户端自带工具或状态。
- 同步成功时走真实接口；同步失败或未配置接口时允许本地回退。
- 停止必须 abort 请求，不把取消显示成故障。
- 提案必须明确“尚未写入”，不得伪造执行成功。
- 保持现有 Agent 首页结构，只替换单一 Agent 回合的数据来源与状态。

## 3. 能力与场景

### R1 服务端项目状态

Given 当前会话拥有项目
When 请求 `POST /api/mobile/agent`
Then 服务端从该项目最新快照构建 AgentState，并执行最多 3 轮的现有 ReAct 循环。

并且项目不存在、不属于当前会话或输入不合法时返回 400。

### R2 只读与提案工具

Given 模型要求调用工具
When 执行 `get_project_status`、`audit_shots`、`review_episodes`、`get_quota`、`search_docs` 或 `propose_*`
Then 服务端返回真实工具结果或待确认卡片。

并且接口不写镜头、不生成资产、不改项目快照。

### R3 额度与降级

Given 服务端循环调用模型
Then 每次模型往返按现有 Agent 额度扣减，并返回实际调用次数。

Given 模型当前不支持 tools
Then 降级为一次无工具回答，并明确标记 `degraded`。

### R4 移动端执行

Given 工作区已同步
When 用户发送问题
Then App 调用真实 Agent 接口，执行中可停止，失败保留输入并可重试。

Given 工作区未同步
Then 继续使用本地回退结果，不请求真实接口。

### R5 结果呈现

Given 接口返回回答
Then 在现有 AI 场记区域展示回答与真实工具步骤。

Given 返回 shot-edit 或 regenerate 卡片
Then 展示一条待确认建议；采纳动作只进入“已保留建议”状态，不宣称写入项目。

## 4. 验证

- Agent prompt/state/loop 单元测试通过，覆盖工具调用、额度次数、卡片和非法输入。
- 移动端 API、映射、停止和错误状态测试通过。
- 根项目与移动端 TypeScript 检查、全量测试和构建通过。
- 使用 mock Agent 响应完成 390/375 截图，覆盖执行、回答、提案、停止和失败。
- 真实模型调用不纳入自动测试，避免测试环境消耗额度。

## 5. 当前验收

- 根项目 455 条测试通过，移动端 31 条测试通过。
- 移动端逻辑层行覆盖率 99.69%、分支覆盖率 84.13%、函数覆盖率 100%。
- 根项目与移动端 TypeScript 检查、`next build`、`expo export --platform web` 通过。
- `/api/mobile/agent` 的空白输入与无权限项目返回 400，且不触发模型调用。
- mock Agent 已验证请求体包含真实项目 ID、普通回答、工具轨迹、提案、保留、停止、失败和重试。
- 390×844 与 375×812 截图通过，无横向溢出和运行时错误。
- 真实 DeepSeek 往返、额度扣减结果和工具模型兼容性尚未在自动测试中消费真实额度验证。
