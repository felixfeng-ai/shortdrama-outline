# 短剧项目附赠小说稿

## 目标

在现有短剧项目上增加一个可选的小说稿产物。小说不是第七个剧情步骤，也不成为新的工作台首页；入口位于项目导出菜单，进入独立的小说编辑工作区。

小说默认不生成、不导出。用户必须主动选择篇幅并确认预算后，系统才开始生成。小说任务始终低于图片、视频、音频和成片渲染任务的优先级。

## 能力点

### N1 篇幅与预算

- 提供中篇版、标准长篇版、长连载版三种预设。
- 默认不选中任何预设。
- 生成前展示预计章节数、字数、Token、平台额度和耗时区间。
- 预算由纯函数计算，前后端共用同一口径。

验收场景：

- Given 用户首次进入小说工作区，When 页面加载完成，Then 不出现已选中篇幅，也不自动创建生成任务。
- Given 用户选择标准长篇版，When 请求预算，Then 返回 80-100 章、20-25 万字及对应 Token、额度和时间区间。

### N2 复用短剧事实

- 只读取项目最新正式快照和项目上下文。
- 复用一句话想法、Brief、Look、人物、三幕、分集、场次、分镜中的动作和台词、视觉角色、地点、Canon、判断记录与项目原文。
- 不把镜头提示词、景别、运镜、画幅、时长、参考图路径和媒体文件写入小说正文上下文。
- 保存来源快照 ID 和内容签名，用于判断章节是否过期。

验收场景：

- Given 项目已有完整六步快照，When 构建小说来源包，Then 来源包包含叙事事实、人物和 Canon，不包含 `Shot.prompt`。
- Given 上游快照发生变化，When 打开已有小说，Then 受影响章节标记为过期，但正文不被自动覆盖。

### N3 卷章规划

- 根据目标字数和章节数确定性规划卷、章和章纲。
- 一集可以拆成多个章节，但每章必须回指来源集数。
- 章纲包含目标字数、冲突、转折、结尾钩子和来源场次。
- 不默认生成 120 章；章节数由用户选中的篇幅决定。

验收场景：

- Given 30 集项目选择标准长篇版，When 规划目录，Then 生成 90 章并分成 6 卷。
- Given 用户修改章节标题或章纲，When 保存，Then 正文 revision 增加且旧内容保留为历史版本。

### N4 低优先级生成

- 一次只处理少量章节，并把游标持久化。
- 项目存在排队或运行中的图片、视频、音频、成片任务时，小说生成停止领取下一章。
- 前端轮询进度，页面离开后任务状态仍可恢复。
- 重复生成请求通过幂等键返回同一运行任务。

验收场景：

- Given 项目有运行中的视频任务，When 小说生成 tick 执行，Then 小说保持等待且不调用模型。
- Given 小说运行到第 12 章，When 用户暂停并稍后继续，Then 从第 13 章继续。

### N5 质量检查与去 AI 味

- 确定性检查工程词泄漏、机械句式、重复 n-gram、占位符、截断、字数偏离和章末钩子。
- 去 AI 味只生成候选修订，不自动覆盖正文。
- 用户确认候选后才写入新版本。
- 改稿不得新增事实、角色、事件，不得改变人物选择和 Canon。

验收场景：

- Given 章节包含“分镜、景别、首帧、Prompt”，When 执行质检，Then 返回工程词问题且阻断导出前提示。
- Given 用户只执行检查，When 检查结束，Then 正文 revision 不变。

### N6 导出

- 支持 Markdown、TXT、DOCX、EPUB 和 ZIP。
- 项目完整备份默认包含小说；普通交付包只有在用户勾选时才包含小说。
- 导出内容包含书名、卷章、正文、来源信息和 AI 声明。
- manifest 记录模型、Prompt 版本、来源快照和导出时间。

验收场景：

- Given 小说已有 3 章，When 导出 Markdown，Then 包含书名、三章正文和 AI 声明。
- Given 小说尚未生成完成，When 导出，Then 文件只包含已完成章节并在 manifest 标记未完成。

### N7 入口与视觉

- 导出菜单增加“小说稿”入口，并跳转到 `/novels/[projectId]`。
- 工作区不增加主导航。
- 桌面端使用左侧卷章树、中间正文编辑、右侧 Canon/质检的编辑台布局。
- 移动端折叠为“目录、正文、检查”三个视图，不出现横向溢出。

验收场景：

- Given 当前项目已有内容，When 打开导出菜单，Then 能看到“小说稿”。
- Given 390px 视口，When 打开小说工作区，Then 主动作和正文仍可达，页面没有横向滚动。

## 数据与接口边界

- 小说独立于六步快照，表结构从数据库 Migration 22 开始。
- 章节正文与版本 append-only。
- API 必须校验项目访问权限、统一响应信封、独立 `novel` 限流组。
- 所有生成接口先限流、再检查预算，最后调用模型。

## 非目标

- 不保证文本能通过任何第三方 AI 检测。
- 不自动上架番茄或其他平台。
- 不默认生成、不默认 120 章、不自动批量改写整本书。
