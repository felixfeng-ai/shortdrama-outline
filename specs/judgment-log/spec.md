# 能力点：判断日志

## 背景

创作者每天都在做判断：换掉一个角色、重跑一版大纲、否掉一个方向。
现在这些动作只留下结果，没留下**理由**。结果是：场记不知道你否过什么，
下一轮还会给出同样的建议；换个人接手，也看不出"为什么当时不这么做"。

判断日志是 [JUDGMENT.md](../../JUDGMENT.md) 的 P0，和意图卡一起上线：
意图卡记录"想拍什么"，日志记录"为什么不要什么"。

外部验证：`drama-skills` 的创作简报里已有"明确拒绝的方向"一栏——
说明"记录否决理由"是真实工作流的一部分，只是目前靠手写 markdown。

## Requirements

### R1 · 一次点击就能记，也可以不写

- 触发点：换一个 / 重生成 / 否决提案。
- 记录：时间、步骤、动作、可选的一句理由。
- 不写理由也能继续；不弹窗、不拦截。

**Scenario**

```gherkin
Given 用户在人物步骤点了「换一个」
When 不填写任何理由
Then 正常换人，并且日志里多一条无理由的动作记录
```

### R2 · 理由会成为后续上下文

- 同一项目的场记可以读到最近的判断记录。
- 回答里可以引用，例如"你之前否掉过这个方向，因为太苦"。
- 不把整份日志塞进每次 prompt：只取最近 N 条 + 当前步骤相关。

**Scenario**

```gherkin
Given 用户否决过一次"黑暗结局"，理由写的是"太苦"
When 场记被问到"这一版结局怎么样"
Then 回答里能引用这条理由，而不是重新推荐同一方向
```

### R3 · 默认本地，不悄悄上传

- 日志属于创作者的偏好数据，P0 存本地 / 项目快照。
- 任何跨设备同步必须显式说明，不做后台静默上传。

### R4 · 跟着项目走

- 导出项目包时带上日志；换项目时加载该项目的日志。
- 清空项目时一起清空，不残留到下一个项目。

## 不在本次范围

- 不做团队协作、评论、@人。
- 不做"日志 → 训练个人偏好模型"。

## 验收

1. 换一个 / 重生成后，日志条数 +1，且生成流程没有被阻塞。
2. 不写理由时，日志仍记录动作与时间。
3. 场记的上下文里能看到最近记录，且不撑爆 token（上限 10 条）。
4. 导出包含日志，换项目后互不串台。
