# 平台适配深化

> 状态：已实现，等待产品验收  
> 日期：2026-11-04  
> 优先级：P1，交付可用性

## 1. 目标

让同一份分镜在通用、即梦、可灵、剪映和结构化 JSON 下不仅文件名不同，
还能得到对应的操作说明、差异预检和可直接粘贴的提示词文本。

适配层继续只渲染已有数据，不调用私有 API、不生成平台私有工程、不上传图片。

## 2. 平台 Profile

每个目标提供一份可读的 Profile：

- 目标名称
- 使用模式：通用、首帧图生视频、首尾帧衔接、剪辑装配或结构化自动化
- 一句话适用方式
- 是否需要已采用首帧
- 三步以内的操作清单

Profile 会写入 `manifest.json`，并显示在导出菜单顶部。

## 3. 差异预检

在现有预检之外增加：

- 空提示词：阻断。
- 视频类目标缺少已采用首帧：提醒；只有调用方提供真实采用图清单时才判断。
- 提示词超过 1200 字：提醒。明确写为“可读性检查”，不冒充平台官方硬限制。
- 原有参数、锚点、禁图、末镜衔接检查保持。

## 4. 交付文件

每个平台目标在原有文件外增加：

- `copy-prompts.txt`：只含按集镜编号的纯提示词，方便直接粘贴。
- `platform-guide.md`：Profile、操作顺序和导出前检查项。
- `manifest.json.profile`：同一份能力说明，供外部工具读取。

不得写入 Authorization、API Key 或未经核实的私有字段。

## 5. UI

- 导出菜单选择目标后显示 Profile 的一句话说明。
- 不新增页面或弹窗。
- 桌面和手机端均可换行，不挤坏导出按钮。

## 6. 非目标

- 自动登录或提交到第三方平台。
- 猜测平台私有 API。
- 根据平台名称改写镜头内容本身。
- 把“超过 1200 字”说成平台拒收原因。

## 7. 验收

1. 五个平台目标各有不同 Profile。
2. 空提示词阻断；缺首帧和超长提示词提醒。
3. 即梦、可灵交付包含纯提示词粘贴文件和操作说明。
4. `manifest.json` 带同一 Profile。
5. 不改动原始镜头 prompt。
6. 全量测试、TypeScript、生产构建通过。
7. 桌面 1440 和手机 390 导出菜单无溢出、无浏览器错误。
