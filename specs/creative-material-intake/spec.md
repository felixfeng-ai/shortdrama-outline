# 创意与素材入口

## 目标

把 Skill 首页从单一想法输入框升级成可区分创作起点的入口，并让小说、剧本等文本素材真正进入当前项目的创作上下文。用户发送任务前必须能看见本次会读取什么、Skill 前置是否满足、会产出什么、是否写入项目。

## P0 能力点

### I1 · 三种创作起点

- 提供“从想法开始 / 从小说剧本开始 / 继续当前项目”三个互斥模式。
- 模式切换保留各自草稿，并同步到 URL，返回页面后能恢复。
- 每个模式使用不同占位、辅助说明和快捷任务，不再把所有需求塞进同一种输入。

### I2 · 项目原文资产

- 支持 TXT / Markdown 原文读取；不把 DOCX / PDF 伪装成已解析。
- 原文以当前项目为边界持久化，包含名称、类型、字数、内容和更新时间。
- 同一项目相同内容去重，删除素材只解除当前项目引用。
- 原文写入和读取必须校验项目归属；项目删除后级联清理。
- 图片继续遵守本机存储边界，不进入服务端原文表。

### I3 · 发送前预检

- 输入区展示本次将读取的项目标题、集数、创作意图、原文数量和所需项目步骤。
- 选中 Skill 后展示其前置条件、产出和写入边界。
- 前置条件缺失时明确说明缺什么，但不由前端直接扣额度或写入项目。

### I4 · Agent 使用真实原文

- 发送给 Agent 的上下文使用项目原文摘要，而不是只有文件名。
- 原文上下文有明确字符预算，超长内容截断并说明。
- 未选中 Skill 时可交给场记匹配；选中 Skill 时继续复用现有 Agent / Runner 链路。

## 验收场景

### Scenario I1

**Given** 用户在“从想法开始”写了草稿

**When** 切到“从小说剧本开始”再切回

**Then** 两个模式各自保留草稿，URL 反映当前模式。

### Scenario I2

**Given** 用户给当前项目加入一份 12,000 字 TXT 剧本

**When** 刷新页面

**Then** 剧本仍在当前项目素材中，并显示真实字数。

### Scenario I3

**Given** 用户选择“镜头连续性检查”但项目没有分镜

**Then** 输入区显示“缺少分镜”的前置提醒。

### Scenario I4

**Given** 当前项目已有原文素材

**When** 用户交给场记改编

**Then** 场记上下文包含原文摘录和项目集数，而不是只包含文件名。

## 不在本期

- DOCX / PDF 解析。
- 图片像素上传或跨设备图库同步。
- 自动把原文改写成 Canon、人物或分镜。
