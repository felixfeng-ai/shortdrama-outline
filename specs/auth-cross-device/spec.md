# 正式账号与跨设备项目归属

> 目标：用户登录后，Web、PWA 与 App 能通过同一账号访问同一个项目。

## 1. 能力

- 手机号请求 6 位验证码，验证码 5 分钟有效。
- 验证码只保存哈希，不保存明文；每手机号有发送冷却和小时上限。
- 验证成功创建或复用用户，并签发 30 天会话。
- Web 使用 HttpOnly Cookie；App 使用同一会话 token 作为 Bearer Token。
- 登录时把当前匿名会话项目认领到正式用户。
- 用户只能看到自己的项目、快照、任务、关键帧和推送订阅。

## 2. 生产边界

- 未配置正式短信通道时，生产环境不得返回固定验证码。
- 本地开发允许返回 `devCode`，仅用于本机联调。
- 会话 token 只存哈希；退出登录立即撤销会话。
- 匿名项目认领只能发生一次，不能认领其他匿名会话的项目。
- 当前本地图库和相册原图仍不跨设备同步。

## 3. 场景

### T1 请求与验证

**Scenario T1.1**
Given 用户输入合法手机号
When 请求验证码
Then 服务端保存验证码哈希，并在开发环境返回可联调的 devCode。

**Scenario T1.2**
Given 验证码正确且未过期
When 用户提交验证
Then 创建用户、签发会话并返回用户信息。

### T2 项目认领

**Scenario T2.1**
Given 当前浏览器有匿名项目
When 匿名用户首次登录
Then 该项目归属切换到正式用户。

### T3 跨端

**Scenario T3.1**
Given Web 已登录
When App 使用同一 Bearer Token 请求项目列表
Then App 读取到同一用户的项目。

## 4. 验收

- 手机号、验证码、会话、退订和认领均有测试。
- 所有项目数据接口使用统一 owner 解析。
- 全量测试、类型检查、生产构建和 Web/API 浏览器验收通过。

## 5. 独立登录页

登录属于需要完整焦点和稳定输入环境的长表单，不使用覆盖工作台的 modal。

### Scenario L1 从工作台进入登录页

**Given** 用户未登录并停留在任意工作台步骤

**When** 用户点击顶栏登录入口

**Then** 浏览器进入 `/login` 独立页面，不出现覆盖工作台的弹层，并保留登录后返回当前工作台 URL 的路径。

### Scenario L2 登录后安全返回

**Given** 登录页收到 `next` 参数

**When** 用户完成验证码登录

**Then** 只允许跳转到站内绝对路径；外域、协议相对地址和脚本地址一律回到 `/`。

### Scenario L3 表单状态完整

**Given** 用户正在登录页

**When** 用户获取验证码、输错验证码或在手机号与验证码步骤间切换

**Then** 页面提供可见标签、内联错误、加载态、倒计时与返回修改手机号的入口，移动端无横向溢出。
