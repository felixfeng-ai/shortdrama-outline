# Production Hardening P2

> 本轮把动态分镜的分享视频导出纳入真实浏览器门禁，并修正导出时阻断播放器的问题。

## R1 导出不阻断播放

Given 当前动态分镜为 `ready`
When 用户确认导出分享视频
Then 导出弹层立即关闭，播放器控制继续可用
And 页面持续显示真实的“正在渲染分享视频”状态
And 成功后在当前播放器出现 MP4 与 SRT 下载入口
And 失败时重新打开弹层并显示具体错误

## R2 真实产物

Given 示例项目包含 5 张已采用首帧
When 浏览器通过正常 UI 导出
Then 生成 30 秒竖屏 MP4 与独立 SRT
And MP4 含视频轨和系统 BGM 音频轨
And SRT 保留真实说话人与对白
And 刷新页面后仍能读取已完成的导出记录

## R3 CI 安全

- E2E 明确设置 `TTS_ENABLED=0`，不得调用真实付费语音。
- 下载后的 MP4 必须由 FFprobe 验证，不接受仅凭按钮出现判定成功。
- 桌面与 390px 移动端导出弹层、导出中状态和下载结果都必须截图验收。

## 非目标

- 不接入新的 TTS 供应商。
- 不验证真实付费 TTS smoke test。
- 不在本轮重新设计播放器或导出视觉语言。
- 不新增漫剧、发布平台自动上传或外部视频回传。

## 验收

- 浏览器 E2E 覆盖导出确认、非阻断状态、下载、重载持久化。
- FFprobe 验证约 30 秒 MP4、视频轨和音频轨。
- SRT 内容验证真实对白。
- `npm test`、`npx tsc --noEmit`、`npm run build`、`npm run test:e2e:core` 通过。
