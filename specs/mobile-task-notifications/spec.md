# 手机端任务完成提醒（PWA 前台）

## 1. 目标

让用户知道生成任务已经结束，不必反复打开任务页检查；同时为后续真正的 Web Push 建立任务终态、未读状态和通知点击落点。

## 2. 边界

- 本轮只做 PWA 前台通知：页面打开期间收到生成更新后发送系统通知。
- 不声称 App 完全关闭后仍能收到推送；后台 Web Push 需要 VAPID、订阅存储和服务端发送，另行实现。
- 不自动请求通知权限；只在用户点击“开启系统通知”后请求。
- 通知只覆盖当前项目的关键帧生成任务，状态为 succeeded / failed / canceled。
- 首次加载已有任务只建立基线，不为历史任务补发通知。
- 未读角标和通知去重状态存本地，不进入项目正文、导出包或服务端数据库。

## 3. 能力与场景

### N1 任务终态识别

**Requirement**：只有任务从非终态变成终态，或出现新的终态任务时，才产生提醒。

**Scenario N1.1**
Given 首次加载已有任务
When 建立提醒基线
Then 不产生未读，不为历史终态任务发通知。

**Scenario N1.2**
Given 某任务上次为 queued 或 running
When 它变成 succeeded、failed 或 canceled
Then 该任务进入未读集合，并可产生一条系统通知。

**Scenario N1.3**
Given 某任务已经成功且已提醒
When 同一状态再次读取
Then 不重复增加未读或重复通知。

### N2 任务入口角标

**Requirement**：未读任务通过底部“任务”入口明确展示。

**Scenario N2.1**
Given 当前不在任务页且存在未读终态任务
Then 任务入口显示数量角标，超过 9 时显示 `9+`，并以无障碍标签说明未读数。

**Scenario N2.2**
Given 用户切换到任务页
Then 未读清零并持久化，任务入口角标消失。

**Scenario N2.3**
Given 用户刷新或重新打开 App
Then 已清除的未读不会重新出现，新产生的未读仍会恢复。

### N3 系统通知授权

**Requirement**：系统通知由用户显式开启。

**Scenario N3.1**
Given 浏览器支持通知且尚未授权
When 用户打开“我的”
Then 显示“开启系统通知”按钮，不自动弹出权限请求。

**Scenario N3.2**
Given 用户点击开启并允许
Then 显示已开启状态；新终态任务可通过 Service Worker 发出通知。

**Scenario N3.3**
Given 浏览器不支持通知、非安全上下文或权限被拒绝
Then 显示明确状态，不反复请求，也不影响任务页使用。

### N4 通知点击

**Requirement**：点击系统通知直接进入任务页。

**Scenario N4.1**
Given 用户点击成剧任务通知
Then Service Worker 聚焦已打开的成剧窗口并导航到 `/?app=tasks`，或打开新窗口。

## 4. 验收

- 终态转换、首次基线、去重和未读恢复有单元测试。
- 任务入口角标与通知授权状态有 App 回归测试。
- Service Worker 声明 notificationclick，并落到任务页。
- 通知权限按钮触控目标不小于 44px，状态不只靠颜色表达。
- 全量测试、类型检查和生产构建通过。
