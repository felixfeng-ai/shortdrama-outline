# 结构化决策与判断日志

## 目标

把“选了什么、为什么、是否锁定”从浏览器日志升级为服务端项目资产，并让 AI 场记读取历史决策、提出待确认决策卡。

## 能力点

### S1 数据库迁移

- 新增 `project_decisions` 与 `project_judgments`。
- 两者随项目删除级联清理。
- 通过现有编号迁移机制执行。

### S2 结构化决策

- 决策字段包含步骤、目标、问题、候选方案、最终选择、理由、状态、置信度、锁定状态和影响范围。
- 状态为 `proposed / accepted / rejected / locked`。
- 同一项目内按更新时间倒序读取。
- 决策创建和更新必须校验项目归属。
- 锁定决策不能被普通更新改成其他状态，必须先明确解锁。

### S3 判断日志

- 每次接受或否决决策时写入一条判断日志。
- 现有 `recordJudgment` 改为同时写服务端。
- 项目首次加载时，服务端无判断日志则迁移本地旧日志；迁移后保留本地缓存。
- 判断日志按项目隔离，最多返回最近 100 条。

### S4 Agent 决策卡

- Agent 状态新增最近决策。
- 新增只读工具 `get_decisions`。
- 新增提议工具 `propose_decision`，只返回待确认卡片。
- 用户确认后调用决策 API，落库为 `accepted` 并写判断日志。
- 用户忽略时不写服务端。

### S5 最小可见 UI

- 项目状态区新增“决策”入口。
- 显示问题、当前选择、理由、状态和是否锁定。
- 已锁定决策有明确标识。
- Agent 决策卡沿用现有待确认卡片样式。

## 不在本阶段

- 决策多人投票
- Canon 冲突校验
- 决策影响自动重跑
- 决策与具体角色字段直接绑定
- 审批权限

## 验收场景

1. Given 新项目，When 创建决策，Then 状态和字段被规范化并落库。
2. Given accepted 决策，When 用户锁定，Then 状态变为 locked。
3. Given locked 决策，When 普通更新尝试改成 rejected，Then 拒绝并提示先解锁。
4. Given Agent 提议决策，When 用户确认，Then 创建 accepted 决策并追加判断日志。
5. Given 旧浏览器判断日志，When 首次打开项目，Then 自动迁入服务端。
6. Given 另一个 owner，When 读取项目决策，Then 返回 403。
