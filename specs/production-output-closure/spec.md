# Production Output Closure

> 本轮只处理成片、产物、交付状态和链路验收。漫剧继续保留在
> `docs/comic-production-roadmap-2026-11-11.md`，不进入当前实现。

## 目标

让用户在项目产物中心直接回答四个问题：

1. 这集有没有可播放成片？
2. 如果没有，下一步最应该做什么？
3. 成片、交付包和发布记录分别在哪里？
4. 创作版本和最终成品之间是什么关系？

## 能力点

### R1 成品优先的产物中心

Given 用户打开项目产物中心
When 项目已有渲染、交付包或创作快照
Then 默认进入“成品”页签，先展示最终产物和唯一下一步
And “创作产物”“确认队列”作为次级页签保留

### R2 四层产物口径

Given 用户查看项目产物
Then 页面明确区分：

- 创作产物：故事、人物、三幕、分集、定妆、场次、地点、分镜
- 成片：预览版和正式交付版渲染
- 交付物：字幕版、干净版、封面、manifest 和 ZIP
- 发布记录：平台、作品链接、发布时间和播放数据

不得把快照版本、成片、交付包和发布记录混成同一种“产物”。

### R3 真实视频作为成片主角

Given 项目存在成功渲染
When 用户打开成品页签
Then 页面显示可播放视频、集号、版本、清晰度、时长和下载入口
And 页面只突出一个与当前状态匹配的主操作

Given 项目没有成功渲染
Then 页面显示真实阻断原因和“去生成成片”入口
And 不得用空播放器、假进度或占位视频冒充成片

### R4 全项目成片读取

Given 产物中心需要跨集展示成片
When 客户端读取渲染记录
Then `fetchVideoRenders` 允许省略集号并读取当前项目全部集
And 原有按集读取调用保持兼容

### R5 真实生产黄金路径

Given 项目已有镜头和已采用视频
When 执行时间线固化、FFmpeg 渲染、字幕生成和交付包构建
Then 测试必须产出可解析的 MP4、SRT、manifest 和 ZIP
And 验收记录必须来自真实文件，不来自 mock 状态

### R6 术语收敛

Given 用户未进入高级渲染设置
Then 主流程只使用“镜头”“成片”“下载”“交付包”四类词
And “固化”“时间线版本”“渲染队列”继续存在，但降级为高级信息

### R7 状态完整性

Given 成品页签处于加载、空、失败、运行或成功状态
Then 每种状态都有明确反馈
And 1440px 与 390px 均不得出现横向溢出、文字遮挡或控制项超出容器

## 非目标

- 本轮不接入第三方平台自动发布。
- 本轮不把单实例渲染队列升级为分布式队列。
- 本轮不引入漫剧分格、页漫或条漫产物。
- 本轮不修改计费口径。

## 验收

- 新增成品信息架构和全项目渲染读取的源码测试。
- 新增真实 FFmpeg 渲染到交付 ZIP 的黄金路径集成测试。
- 产物中心默认成品页签，桌面和 390px 浏览器实测无控制台错误。
- `npx tsc --noEmit`、全量测试和生产构建通过。
