# Production Hardening P8

> 本轮打通本地参考图目录的授权恢复，避免浏览器撤销权限或目录失效后，
> 工作台把“读不到”伪装成“没有图片”，并静默清空用户现场。

## R1 目录权限状态

Given 浏览器支持 File System Access
When 工作台加载已保存的素材目录句柄
Then 只查询读取权限，不在页面启动时主动弹出授权框
And 状态必须是以下之一：
- `not-connected`：没有保存过目录
- `connected`：读取权限有效
- `needs-permission`：权限为 prompt、拒绝或用户取消
- `missing`：目录已移动、改名或删除
- `error`：其他读取错误

When 用户主动点击“重新授权素材文件夹”
Then 使用 `requestPermission({ mode: "read" })` 申请权限
And 用户取消与浏览器明确拒绝要显示不同原因
And 重新授权成功后立即恢复扫描，不需要刷新页面

## R2 失败时保留现场

Given 工作台内存里已经有一批素材和已挂参考图
When 权限失效、目录缺失或扫描抛错
Then 不执行 `setAllVaultFiles([])`
And 不清空已挂参考图
And 不把失败结果显示为“0 张图片”
And 用户明确看到失败原因和下一步操作

## R3 图库面板

- 目录直连模式显示当前授权状态与一句人话原因。
- `needs-permission` 时主操作是“重新授权素材文件夹”。
- `missing` 时主操作是“重新选择素材文件夹”。
- `error` 时主操作是“重试读取”，并保留“重新选择素材文件夹”出口。
- 已连接且文件数大于 0 时仍提供“重新扫描”。
- 桌面和 390px 宽度下状态行、状态说明和按钮不重叠、不横向溢出。

## R4 已挂参考图健康检查

Given 目录权限有效
When 已挂参考图数量发生变化或目录重新授权成功
Then 使用 `vaultFileExists` 检查已挂引用
And 面板显示“X 张已挂引用暂时读不到”
And 用户可以重新授权或重新扫描，不需要移除项目引用

## 浏览器验收

- 未连接目录时只显示选择入口。
- 授权状态为 prompt 时显示重新授权，不显示 0 张的误导文案。
- 重新授权后素材恢复加载，已挂参考图重新可读。
- 目录扫描失败后原列表仍保留。
- 1440px 和 390px 截图均无横向溢出。

## 非目标

- 本轮不自动修复目录移动/文件改名后的路径。
- 不根据文件 hash 自动重建已改名文件的新路径；该能力需单独设计与验收。
- 不删除用户硬盘上的任何文件。
