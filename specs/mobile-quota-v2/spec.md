# 原生 App · 统一创作额度 v2

## 目标

App 与 Web 使用同一套项目额度口径：按当前项目集数计算一部完整项目成本，不再固定按 10 集基准的 13 单位解释。

## 能力点

### R1 额度 DTO 同步

- 解析 `episodeCount`、`projectCost`、`pricingVersion`。
- 解析 `estimates.selected` 和 `estimates.presets`。
- 缺少新字段时继续使用 `remaining / limit / used / projectsLeft`，兼容旧缓存和旧服务端。
- 数值必须清洗为有限非负整数，非法嵌套估算不阻断工作区加载。

### R2 我的页额度解释

- 主状态显示“可跑 N 个 X 集项目”，不再写无集数限定的“完整项目”。
- 显示当前项目集数、每部约消耗额度和价格版本。
- 展示 10/30/60 集预设各自的项目成本与可跑项目数。
- 余额、已用和进度条继续使用真实额度单位。

### R3 Agent 与媒体成本

- Agent 额度解释继续由服务端统一计算，App 不复制价格表。
- 图片、视频、渲染和 Agent 单轮预算继续使用各自现有的单位展示。

## 验收

- 先写失败测试，再实现。
- App 全量测试、TypeScript 和 Expo Web 导出通过。
- 390/375 宽度额度卡无溢；真实金额和项目数来自服务端返回。
