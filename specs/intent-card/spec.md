# 能力点：导演意图卡

## 背景

现在唯一的输入是一句话想法。模型不知道这部戏要给谁看、要什么情绪、参考什么片子，
只能给"平均值"的结果。结果是：生成能看，但不像"某个人想拍的那部片"。

意图卡是 [JUDGMENT.md](../../JUDGMENT.md) 的 P0：把判断放在生成之前，并让每一步都能引用它。

外部验证（2026-10-19）：`drama-skills`（3.1k★）已有完整的
[`creative-brief.md`](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-develop/assets/creative-brief.md)，
其中包含"项目意图 / 创作者契约 / 节奏档案 / 方向候选与选择理由"。
但它是 9 节 markdown，必须由人手动维护——本能力把它压缩成 5 个字段，
变成项目状态并自动注入。**不照搬 9 节表单。**

## Requirements

### R1 · 可以在生成前填写，也可以跳过

- 字段：核心情绪（单选 + 一句补充）、目标观众（单选）、参考片（最多 3 个名字）、红线（一句话）。
- 全部可跳过；跳过时行为与当前完全一致。
- 不阻塞任何一步生成。

**Scenario**

```gherkin
Given 用户新建了一个项目
When 直接点「生成人物」而不填意图卡
Then 请求与现在完全一致，不出现额外提示
```

### R2 · 意图进入每一步的 prompt

- 填写后，人物 / 三幕 / 分集 / 分镜的 prompt 都带一段「创作意图」约束。
- 约束是**倾向**，不是硬过滤；模型仍要遵守原有的结构要求。

**Scenario**

```gherkin
Given 意图卡填写「情绪：克制」「观众：25-35 女性」「参考：小偷家族」
When 生成三幕大纲
Then prompt 中包含这三项
And 输出仍然满足三幕结构与情节点数量要求
```

### R3 · 修改意图会让下游过期

- 修改意图卡后，已生成的下游步骤标为「基于旧意图」，复用现有 stale 提示。
- 不自动重生成，由用户决定。

### R4 · 存储从轻

- P0 不建表：随项目快照 / 本地记录保存。
- 换项目时恢复该项目的意图；没有则留空。

### R5 · 随项目导出

- 导出项目包时，意图卡写进 `project.json` 的 `brief` 字段。
- 让"这部片想成为什么"能跟着文件一起交给下一个人。

### R6 · 是倾向，不是硬过滤

- 意图只影响语气、取舍与优先级，不覆盖三幕结构、情节点数量、场次下限等既有硬要求。
- 与意图冲突时，结构规则优先。

## 不在本次范围

- 不做意图的 A/B 对比（属于 P1 的「双版本判断」）。
- 不做意图的团队协作与权限。

## 验收

1. 空意图生成与现在逐字节一致（prompt 不追加任何内容）。
2. 填了意图后，四步 prompt 都包含同一段约束。
3. 改意图后，已生成步骤出现过期提示，且不自动重跑。
4. 意图卡不阻塞生成，跳过时不出现二次确认。
5. 导出包里能看到 `brief`，且换项目后能恢复。
