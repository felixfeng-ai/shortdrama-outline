# 首页性能与运营后台 MVP

## 目标

在现有 Next.js + SQLite 单体中降低首页首屏脚本成本，并增加仅管理员可访问的运营后台，覆盖用户、额度白名单、基础运营统计和真实用户 Web Vitals。

## 能力点

### R1 首页按需加载

- 首页默认总览只加载轻量外壳、导航、项目概览和当前上下文。
- Agent、画布、生成、视频、小说、时间线和低频编辑模块改为按需加载。
- 动态组件必须有加载占位，不能因拆包出现空白或布局跳动。
- 首屏 JS 传输相对当前约 488 KB 有明确下降。

### R2 Web Vitals 采集

- Web 端上报 FCP、LCP、INP、CLS、TTFB。
- 记录路由、发布版本、设备类型、连接类型、指标值和评级。
- 不记录用户正文、提示词、邮箱、Token 或生成内容。
- 上报失败不能影响页面交互。

### R3 管理员鉴权

- 只有登录用户且身份命中管理员白名单时可以访问 `/admin` 和 `/api/admin/*`。
- 普通登录用户、匿名用户和未登录用户均返回 403。
- 管理员身份不出现在普通用户的账户响应中。
- 初始管理员通过服务端 `ADMIN_EMAILS` 配置，后续可迁移到 `admin_users`。

### R4 用户与额度白名单

- 管理员可以按用户名或邮箱搜索用户。
- 用户行显示注册时间、最近会话、项目数、今日已用/剩余额度、有效期和当前额度覆盖。
- 管理员可以为用户设置临时额外额度、过期时间和原因。
- 同一用户覆盖为更新而不是重复新增。
- 额度查询必须读取有效覆盖；过期覆盖不生效。
- 设置和撤销额度必须写入管理员审计日志。

### R5 运营总览与性能面板

- 总览显示用户、项目、生成任务、额度消耗、反馈和错误数量。
- 性能面板按路由和端展示 FCP/LCP/INP/CLS/TTFB 的 p50/p75/p95。
- 低样本量必须显示真实样本数，不伪装成稳定趋势。
- `/admin` 使用现有 Signal Desk 视觉语言，桌面 1440 与移动 390 可用。

## 数据边界

- 后台只汇总运营元数据，不展示项目正文、剧本、提示词或生成资产内容。
- Web Vitals 属于公开性能采样，但必须限长、限频和清洗。
- 管理员操作全部审计。

## 验收

- 每个能力点先有失败测试，再实现到通过。
- Web 全量测试、TypeScript 和生产构建通过。
- 使用隔离 SQLite 数据库完成管理员真实流程：
  搜索用户 → 设置额度 → 刷新确认生效 → 查看审计 → 查看 Web Vitals。
- 首页与后台分别完成 1440/390 截图验收。
