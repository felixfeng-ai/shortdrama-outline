# Agent Plan / Act / 回滚

> 用户在既定开发顺序中确认继续实施本项。目标不是让 Agent 自由写库，而是把已有的“待确认提案”补成可审计、可恢复的执行闭环。

## 目标

让用户在执行 Agent 修改前看得懂计划，执行后查得到记录，并且能在不破坏版本历史的前提下撤销最近一次可逆修改。

## 能力点

### AP1 · Plan

- 镜头改写和实体修改卡片显示执行计划：目标、字段、原值、目标值、写入范围、版本处理和回滚能力。
- 计划只描述本次动作，不把只读查询、预算卡或生成任务包装成可写计划。
- 执行主按钮明确写“执行计划”，取消仍不写入项目。

### AP2 · Act

- 用户执行计划时，服务端在一次事务中写入：
  - 当前内容对应的 before 快照（若最新快照已与当前内容一致则复用）；
  - 修改后的 after 快照；
  - 一条 Agent 运行记录，关联两个快照。
- 运行记录包含动作类型、产物类型、目标、字段、摘要、状态和时间。
- 快照或运行记录写入失败时，客户端不得显示修改已成功。

### AP3 · 回滚

- Agent 内提供“执行记录”，显示最近的项目级 Agent 修改。
- 只有状态为 `applied` 且目标产物当前仍指向该记录 after 快照时，才允许回滚。
- 若之后已有新版本，拒绝自动回滚并说明原因，不覆盖用户后续修改。
- 回滚不是删除历史，而是以 before 内容创建一版新快照，并把运行记录标记为 `rolled_back`。
- 回滚成功后，工作台内存状态立即同步为恢复后的真实 payload。

### AP4 · 边界与响应式

- 运行记录按项目与 owner 隔离，未授权项目不能读写。
- 只覆盖文本字段的 `shot-edit` 与 `entity-edit`；生成重跑、决策、预算、TTS、成片和时间线不伪装成可回滚。
- 桌面和 390px 窄屏均可操作，回滚采用二次确认，主要按钮至少 44px。
- 视觉沿用 Signal Desk，不新增第二套主题。

## 非目标

- 不做多卡片一次性事务、跨项目 Agent 操作或自动批量回滚。
- 不回滚已生成图片、视频、音频或第三方付费任务。
- 不用 Agent 运行记录替代项目快照、判断日志或导出审计。
