# 工作台、Skill 与画布的统一项目上下文

## 目标

同一项目在工作台、Skill 页和画布之间切换时，项目、当前步骤和来源界面必须保持一致。画布是可深链、可后退的工作台状态，不再只是内存中的遮罩。

## 能力点

### NP1 · 统一路由状态

- 工作台使用 `project` + `step` 表示当前项目与步骤。
- 画布使用同一地址并增加 `view=canvas`，关闭或进入步骤时移除该参数。
- Skill 页接收并保留同一 `project` + `step`，返回工作台或打开画布时不得跳到固定的分镜步骤。

### NP2 · 浏览器历史

- 工作台打开画布写入一条历史记录；关闭画布回到工作台。
- 浏览器前进/后退必须同时恢复项目、步骤和画布开关。
- 直接访问 `?project=…&step=…&view=canvas` 时，项目恢复后直接进入画布。

### NP3 · 导航文案与归属

- Skill 页主导航的“项目”和“画布”使用当前项目与步骤。
- 画布顶部显示项目名和来源步骤，用户始终知道自己在哪个项目、从哪一步进入。
- 没有项目时只生成安全的工作台或 Skill 首页地址，不输出空项目参数。

### NP4 · 响应式与可访问性

- 导航与画布项目上下文在 390px 不横向溢出。
- 当前页面/界面必须有明确选中态，主要导航触控目标不小于 44px。
- 保留现有 Signal Desk 视觉和柔和画布进出动画。

## 非目标

- 不新增独立 `/canvas` 页面。
- 不把画布节点状态复制进 URL；节点选择仍属于画布内部交互。
