# 创作入口与成片叙事

## 目标

平台已经从“分镜提示词工具”扩展为一句话或已有剧本到镜头视频、声音与最小成片的制作工作台。导航和对外文案必须反映这一事实，不能让用户只在完成分镜后偶然发现视频能力。

## 导航命名

### Requirement

面向中文创作者的主入口使用“创作技能”，英文 `Skill` 只可作为内部技术名称。

### Scenario N1

Given 用户位于工作台
When 查看顶部导航和桌面左轨
Then 能看到“创作技能”或“技能”入口，而不是只有裸英文 `Skill`

### Scenario N2

Given 用户打开 `/skills`
When 阅读页面标题、搜索和分类
Then 主文案使用“创作技能 / 创作技能库”，并说明技能会先展示读取范围、产出和确认边界

## 视频工作区

### Requirement

第 6 步提供三个平级视图，视频入口不再藏在长页面中部。

### Scenario V1

Given 用户已经生成分镜
When 进入第 6 步
Then 可以看到“分镜”“镜头视频”“时间线成片”三个页签

### Scenario V2

Given 用户选择“镜头视频”
Then 只显示视频生成与候选状态，不重复铺开分镜质检与成片时间线

### Scenario V3

Given 用户选择“时间线成片”
Then 显示按集时间线、TTS、BGM、渲染队列和产物下载

## 对外叙事

### Requirement

首页、站点元信息和登录页必须描述“故事到成片”的完整链路，不再停留在“能出图的分镜”。

### Scenario C1

Given 用户首次打开站点
Then 首页主题句明确出现分镜、镜头视频和成片

### Scenario C2

Given 用户打开登录页
Then 页面说明角色一致性、镜头视频和时间线成片属于同一条项目链

## 边界

- 路由仍使用 `/skills`，避免破坏已有链接。
- 内部类名、API 和数据结构可以继续使用 `skill` 命名。
- 不增加通用功能市场，不把创作技能做成营销卡片墙。
