# 平台导出适配层

## 目标

让同一份分镜按目标出图/出视频平台产出可直接照单执行的交付文件。适配层只渲染已有镜头数据，不调用平台私有 API，不上传本地参考图，也不把未经核实的字段包装成平台协议。

## P0 能力点

### P1 · 目标选择

- 交付包支持 `通用`、`即梦`、`可灵`、`结构化 JSON` 四种目标。
- 完整备份不受目标选择影响，始终保留完整项目状态。
- 导出界面明确显示当前目标和预检结果。

### P2 · 兼容预检

- 检查时长是否为 5/10 秒档位。
- 检查画幅是否为 9:16 或 16:9。
- 检查出场角色锚点、禁改项和缺失参考图。
- 检查末镜勾选“接下一镜首帧”但没有下一镜的情况。
- 预检结果分为阻断项和提醒项，并写入交付包，不静默丢弃。

### P3 · 可执行交付

- 通用目标保留现有 `production/prompts.csv`、`shotlist.txt`、`chaining.txt`。
- 平台目标额外生成 `production/<target>/prompts.csv`、`shotlist.txt`、`manifest.json`。
- 结构化 JSON 包含 schema、版本、目标、生成时间、预检和全部镜头执行参数。
- 每个平台执行单都按“提示词、参考图、画幅、时长、首尾帧”顺序排列，文案不得虚构平台 API 字段。

### P4 · 性能边界

- 适配只对现有镜头数组做纯函数渲染，不因 30 集导出额外串行请求或逐镜等待。
- 交付包仍复用现有 ZIP 构建器。

## 验收场景

### Scenario P1

**Given** 项目有 30 集分镜

**When** 用户选择“即梦”并导出交付包

**Then** ZIP 内含即梦执行单和结构化清单，且不增加逐镜网络请求。

### Scenario P2

**Given** 某镜时长为 7 秒或缺少角色参考图

**When** 用户做平台导出预检

**Then** 结果明确列出该镜编号与原因，并写入 `export-report.json`。

### Scenario P3

**Given** 用户选择“结构化 JSON”

**When** 打开导出文件

**Then** 可读到稳定 schema、镜头集号、镜号、提示词、参考图、画幅、时长和衔接标记。

## 不在本期

- 即梦、可灵等平台的账号授权和自动提交。
- 猜测或伪造平台私有字段。
- 视频生成、拼接和成片时间线。
