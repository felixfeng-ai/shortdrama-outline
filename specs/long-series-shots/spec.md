# 长剧集分镜分批生成

> 目标：长剧集的场次数超过单次模型输出能力时，分镜仍能按场次顺序稳定生成。

## 1. 能力

- 按场次数量拆分分镜批次，默认每批最多 8 场。
- 每批只把当前场次交给模型，避免一次输出数万 token。
- 后一批提示词携带已生成镜头的简短摘要，保持动作和画面推进。
- 跨批次镜号、`entityId` 连续，不能从 1 重新编号。
- SSE 每批持续推送累计结果，最后一次性写入完整分镜快照。
- UI 能显示当前批次和场次范围。

## 2. 硬边界

- 场次顺序不能改变；同一场次不能重复生成。
- 任一批失败时，不写入半套快照；界面保留已到达的累计结果并显示错误。
- 用户停止生成时保留已到达镜头，不把状态永久停在生成中。
- 每批 token 预算有上限，不能按批数无限放大。
- 参考图、地点锚点、角色锚点规则与单批生成完全一致。

## 3. 场景

### T1 分批规划

**Scenario T1.1**
Given 40 场戏
When 规划分镜批次
Then 得到 5 批，每批最多 8 场，最后一批保留剩余场次。

### T2 跨批连续

**Scenario T2.1**
Given 第二批从第 9 场开始
When 整形第二批镜头
Then 镜号从前面已生成数量继续，`entityId` 不重复。

### T3 承接上下文

**Scenario T3.1**
Given 前一批已有镜头
When 构建后一批提示词
Then 提示词包含前批最后几个镜头的简短摘要，并明确不要重复。

## 4. 验收

- 批次规划、token 预算、跨批编号和 prompt 承接均有测试。
- 原有单批 8 场以内行为保持一致。
- 全量测试、类型检查、生产构建和浏览器流式展示通过。
