# App 创作链路修复

## 目标

让移动端用户能发现主要能力，顺利完成“录音输入 → 生成首帧 → 生成视频 → 审片”链路，并消除底层语音错误对界面的干扰。

## A1 语音输入

**Requirement**：语音输入必须即时反馈，不因输入回调重渲染而中断，也不展示英文底层错误。

**Scenario**：开始录音

- Given 用户已获得麦克风与语音识别权限
- When 用户点击麦克风
- Then 立即显示“正在准备麦克风”或“正在听写”
- And 输入文字更新不会重挂语音监听或触发 abort

**Scenario**：Abort

- Given 语音识别发出 `aborted`
- When 组件卸载或主动停止
- Then 不显示任何红色错误

**Scenario**：真实错误

- Given 语音识别返回无权限、无语音、网络或服务不可用
- When 错误事件到达
- Then 显示可恢复的中文说明
- And 不直接展示底层英文 message

## A2 功能发现

**Requirement**：首页提供清晰的“能做什么”入口，并落到真实能力地图。

- 能力地图覆盖出画面、出视频、整集草片、审片、现场检查、节奏分析、海外审片和任务。
- 每个条目进入现有真实页面，不制造不可用入口。
- 首页只增加一个轻量入口，不堆功能宫格。

## A3 App 内生成首帧

**Requirement**：生成镜头视频缺少首帧时，App 能直接为当前镜头生成首帧。

- 视频模式明确显示缺首帧及原因。
- 提供“在 App 生成首帧”动作，复用当前镜头提示词和本地参考图。
- 首帧生成成功后立即成为当前镜头的可用首帧，无需回到 Web。
- 成功后用户可以继续提交视频任务。
- 若用户不需要先补首帧，提供“直接生成视频”兜底，并明确本次使用文生视频。

## A4 完整链路验证

**Requirement**：使用真实服务跑通一次最小链路。

- 创建或载入示例项目。
- 读取移动上下文和生成目标。
- 生成并采用一张镜头首帧。
- 提交一个符合预算的视频任务。
- 查询任务到终态。
- 审片页能读取生成资产；失败时保留服务端可读错误和恢复路径。

生产服务只在当前分支服务端能力落后时作为验证目标，不把测试项目写进用户已有项目。
