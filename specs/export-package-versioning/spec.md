# 导出包 schema 版本化与迁移

> 状态：已实现，等待产品验收
> 日期：2026-11-04
> 优先级：P1，长期可带走

## 1. 目标

让 `chengju.project` 的字段变化有明确版本和迁移链，旧包不因新增字段静默失效，
新包也不被旧读取器误当作同版本解析。

## 2. 版本口径

- 当前项目包升至 `schemaVersion: 3`。
- v3 固化：AI 声明、项目原文数组、文件清单、报告路径和警告数组。
- 正式支持导入 v2 → v3。
- v1 没有稳定契约，继续拒绝。
- 大于当前版本的包拒绝，并提示升级当前应用。
- 未知 schema 拒绝。

## 3. 迁移

- v2 → v3 是附加迁移：
  - 缺少 `materials` 时补空数组。
  - 缺少 `ai` 时补默认 AI 声明。
  - 缺少 `files` 或 `warnings` 时补空数组。
  - `reportPath` 统一为 `export-report.json`。
- 迁移不修改调用方传入的原始对象。
- 迁移报告包含 `fromVersion`、`toVersion`、`migrated` 和步骤说明。
- v3 包正常读取时 `migrated: false`。

## 4. 导入反馈

- 页面向服务端提交原始 `project.json`，由服务端执行同一迁移。
- 服务端返回 `packageMigration`。
- 页面成功提示中显示“已从 v2 迁移到 v3”。
- 迁移失败时停止导入，不创建半成品项目。

## 5. 兼容边界

- 不猜测无版本字段结构。
- 不把缺少核心数组的包伪装成 v2。
- 不改写图片路径、快照血缘或资产绑定。
- 不把迁移成功表述为数据完整恢复；缺失文件仍进入 warnings。

## 6. 验收

1. 新导出包写 `schemaVersion: 3`。
2. v2 包能导入并补默认字段。
3. v1、v4 和未知 schema 被拒绝。
4. 迁移报告可被 API 与页面读取。
5. 迁移不修改原始输入。
6. 全量测试、TypeScript、生产构建通过。
