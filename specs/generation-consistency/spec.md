# 视觉一致性基础

> 用户已确认继续处理跨角色风格不一致问题。

## 1. 目标

在逐张生成关键帧的前提下，让同一项目的角色定妆图和镜头首帧共享视觉宪法与稳定随机种子，减少色调、光线、镜头语言和整体质感漂移。

## 2. 硬边界

- 不改变“本地参考图不上传”的边界。
- 本轮不把本地参考图或已采用关键帧作为 Provider 图片输入；图生图参考留到下一阶段。
- 视觉宪法为空时，生成提示词与旧行为一致，不凭空添加风格。

## 3. 能力与场景

### V1 视觉宪法注入

**Requirement**：项目视觉宪法必须进入每个平台关键帧生成请求。

**Scenario V1.1**
Given 项目填写了色调、光线、镜头语言或禁区
When 生成角色定妆图或镜头首帧
Then 请求提示词包含统一的项目视觉方向，且不重复插入已有的“视觉宪法”块。

**Scenario V1.2**
Given 视觉宪法为空
When 生成关键帧
Then 基础提示词保持原样，不附加空标签。

### V2 稳定种子

**Requirement**：同一项目使用稳定的通义随机种子，重生成时保持相对稳定。

**Scenario V2.1**
Given 同一个 projectId
When 连续计算或重新生成
Then 得到相同且位于 `[0, 2147483647]` 的 seed。

**Scenario V2.2**
Given 不同 projectId
When 计算 seed
Then seed 通常不同，避免所有项目画面趋同。

### V3 用户可见状态

**Requirement**：关键帧卡必须明确当前是否带入视觉宪法。

**Scenario V3.1**
Given 视觉宪法已填写
When 用户查看关键帧卡
Then 显示“视觉宪法已带入”和简短的色调/光线摘要。

**Scenario V3.2**
Given 视觉宪法为空
When 用户查看关键帧卡
Then 显示“视觉宪法未填写”，提示存在跨角色风格漂移风险。

## 4. 验收

- 视觉宪法组合、重复检测、空值零变化与 seed 稳定性有单元测试。
- 真实生成请求体包含 seed 和视觉宪法内容。
- 全量测试、类型检查、生产构建与本地浏览器验收通过。
