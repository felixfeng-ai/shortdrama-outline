# 统一创作额度 V2

## 目标

 Web、PWA、App 使用同一账户、同一余额、同一价格版本和同一消费流水。内测阶段保留每日
 65 单位，文本、Agent、小说、图片、视频、TTS 与成片渲染共享该余额。

## 计价口径

- 10 集纯文本项目：13 单位。
- 30 集纯文本项目：19 单位。
- 60 集纯文本项目：28 单位。
- `13` 只能表示 10 集基准项目的成本，不得继续代表所有“完整项目”。
- 图片、视频、TTS 和渲染按独立权重消耗同一余额。

## 收费与免费边界

收费动作：

- 故事联想、人物、三幕、分集、定妆提示词、场次、分镜。
- 普通 Agent 与创作技能中的模型调用。
- 小说生成、章节重写和去 AI 味。
- 图片、视频、TTS 与成片渲染。

免费动作：

- 项目新建、切换、改名、删除和示例载入。
- 项目导入、导出和完整备份。
- 资产库管理。
- 只读 Canon、连续性检查、交付预检和成本分析。
- 审阅链接生成和访问。

## 需求

### QV2-1 统一项目估算

Given 用户拥有 65 单位且未消费
When 用户分别选择 10、30、60 集
Then 系统应返回可完成 5、3、2 部纯文本项目
And Web、PWA、App 与 Agent 必须使用相同结果

### QV2-2 Agent 单轮预算

Given 普通 Agent 对话
When 用户发送一条消息
Then 本轮最多允许 3 次模型往返
And 界面必须在发送前展示最高消耗、完成后展示实际消耗
And Skill 模式按执行计划的独立上限执行

### QV2-3 预扣、结算与返还

Given 用户发起付费生成
When 请求仍在运行
Then 额度应先被预扣
When 结果成功保存
Then 应按实际用量结算
When 供应商失败、超时或取消且没有可用产物
Then 应释放未结算额度
And 同一 `requestId` 重试不得重复扣费

### QV2-4 统一媒体额度

Given 用户发起图片、视频、TTS 或渲染
When 服务端接受任务
Then 应使用与文本相同的余额完成预扣和结算
And 任务失败或取消后返还尚未结算额度

### QV2-5 端间账户一致性

Given 用户已登录
When 用户从 Web、PWA 或 App 消费额度
Then 其他端刷新后应看到相同余额
And 匿名身份在登录认领时必须幂等合并当日流水

## 非目标

- 不追溯修改历史 `usage_log`。
- 不对历史图片、视频或 TTS 任务补扣。
- 第一阶段不接入支付、充值和退款到银行卡。
- 不改变现有项目归属与快照隔离规则。

## 验收

- 65 在 10、30、60 集下分别显示 5、3、2 部。
- 普通 Agent 一轮绝不生成第 4 次模型调用。
- 失败请求不留下最终消费流水。
- 相同请求重试只产生一次最终结算。
- 图片、视频、TTS 与渲染不绕过统一余额。
- Web 与移动端读取同一额度事实源。
- 全量测试、类型检查和生产构建通过。
