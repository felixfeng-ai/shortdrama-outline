# 镜头连续性 Skill Runner

## 目标

让“镜头连续性检查”成为可执行的官方 Skill，而不只是把 Skill 名称塞进模型上下文。Runner 直接读取项目最新分镜、角色视觉、地点视觉和生成图台账，复用现有确定性 QC 规则，输出可逐镜处理的返修队列。

## P0 能力点

### C1 · 确定性检查

- 检查当前项目最新一版 `shots`、`visualCharacters`、`visualPlaces` 与 `generatedAssets`。
- 复用 `auditShotProduction`，覆盖缺锚点、缺禁改项、缺参考图、不支持时长和旧参考图。
- 报告必须保留集号、镜号、场景、镜头状态、问题代码和具体原因。
- 报告按集号、镜号稳定排序。

### C2 · 返修队列

- 每个有问题的镜头进入返修队列，同一镜头的多个问题合并。
- 每个问题给出明确动作：补 Prompt、补参考图、改参数或重做镜头。
- 报告只提出动作，不执行写入。

### C3 · 只读边界

- 不调用文本或图片模型。
- 不写快照、任务、生成图或项目更新时间。
- 不扣任何额度。
- 响应明确标记 `writes: false`、`modelCalls: 0`、`quotaCharged: 0`。

### C4 · 项目安全

- API 只允许当前身份访问自己的项目。
- 缺少项目或无权限时沿用平台统一错误信封。

### C5 · Skill 页面接入

- 选择“镜头连续性检查”后优先调用确定性 Runner。
- 页面直接展示汇总、具体镜头问题和处理顺序。
- Runner 失败时才回退到现有 Agent 对话链路。

## 验收场景

### Scenario C1

**Given** 项目第 3 镜缺苏婉定妆图，且参考图版本晚于镜头采用图

**When** 运行镜头连续性检查

**Then** 报告将第 3 镜列入返修队列，并同时给出缺参考图与旧参考图原因。

### Scenario C2

**Given** 项目有 30 集分镜

**When** 运行检查

**Then** 报告可按集号定位问题，不把不同集的镜号混在一起。

### Scenario C3

**Given** 检查前后读取同一项目

**When** Runner 执行完成

**Then** 快照数量、生成图数量和项目更新时间都不变，额度也不变。

### Scenario C4

**Given** 另一个匿名会话请求该项目

**When** 调用 Runner API

**Then** 返回 403，且不泄露项目内容。

## 不在本期

- 自动修改 Prompt 或镜头状态。
- 自动生成缺失参考图。
- 跨项目复用检查规则。
- 把 Runner 结果写成新快照。
