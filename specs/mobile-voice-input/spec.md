# 原生 App 语音识别启动

## 目标

修复点击麦克风后提示“语音识别没有启动，请稍后重试”但无法判断真实原因的问题。

## 原因与边界

- 麦克风权限已授予，不代表设备存在可用的语音识别服务。
- 部分 Android ROM 没有 Google 语音服务、默认识别器未启用，或者配置了不可用的识别服务。
- 原实现只检查权限，没有检查 `isRecognitionAvailable()` 和 Android 识别器列表。
- 原实现把 `client`、`unknown` 等原生错误统一映射为泛化文案，丢失了真实原因。
- 组件卸载时无条件 `abort()` 可能产生迟到的中断事件。

## 能力点

### R1 启动前检查设备能力

- 启动识别前调用 `isRecognitionAvailable()`。
- Android 额外读取可用语音识别服务列表，空列表时不调用 `start()`。
- 能力检查失败时显示可执行的系统设置说明，不显示泛化错误。

### R2 原生错误可诊断

- `client` 错误提示语音服务启动失败并建议检查系统语音服务。
- `unknown + aborted` 作为控制流忽略，不作为红色错误提示。
- 其他 `unknown` 提示系统语音识别被中断，可重试。
- 不向用户暴露英文原生日志或内部包名。

### R3 生命周期安全

- 只有当前确实处于识别状态时，组件卸载才调用 `abort()`。
- 权限暂存、启动中和识别中状态互斥，重复点击不会同时启动多次。

## 验收

- 设备和错误映射有纯函数测试。
- Agent Composer 接线测试覆盖能力检查和条件 abort。
- App 全量测试与类型检查通过。
- 真机验证仍需 Android 与 iOS 各一台设备。
