## 1. 背景

当前平台已经覆盖：

1. 一句话想法到人物、三幕和分集。
2. 角色视觉定妆、地点锚点和场次剧本。
3. 分镜、逐镜 Prompt、首帧关键帧和批量生图。
4. 导出到即梦、可灵、剪映以及结构化 JSON。

用户验证后认为平台仍处于视频生产上游：分镜和首帧已经可用，但缺少逐镜视频、镜头采用、声音和按集成片，用户无法在平台内看到“这一集能不能成”。

竞品正在把视频片段纳入主工作流：

- Toonflow 将剧本、角色、分镜和视频片段放在同一画布，并提供 Agent 与 MCP。
- Jellyfish 已覆盖镜头准备、图片/视频任务编排、全局任务中心和资产回写。
- 虾客漫覆盖小说/剧本、角色场景、故事板、视频片段和成片合成。
- Micro-Drama-Skills 已提供分镜到 Seedance 批量视频任务的技能化流水线。
- Flova 已覆盖项目容器、资产、Agent、Skill、时间线 Edit、音频、最终视频和 CapCut 草稿导出。
- 小云雀已公开短剧 Agent、剧本上传/创作/重制、Seedance 2.5、技能与风格库，以及 Web/App 一体化体验。
- LibTV 已公开无限画布、Agent、3D-BOX、多模型视频、图片、音频、剧本生成和智能剪辑。

因此，本期不是增加一个孤立的“生成视频”按钮，而是补齐：

```text
分镜 -> 平台内视频生成 -> 候选采用 -> 时间线编排 -> 配音/字幕/BGM -> 成片导出
                    \-> 继续导出到即梦、可灵、剪映
```

## 2. 产品决策

### 2.1 双路径并存

保留现有外部交付路径，同时新增平台内视频生产路径。

- 外部路径：即梦、可灵、剪映、通用清单和 JSON。
- 平台路径：首帧或已托管参考图 -> 视频生成 -> 镜头采用 -> 时间线编排 -> 声音与字幕 -> 成片。
- 两条路径不互斥，也不要求用户二选一。
- 平台内生成失败或被取消时，原有导出能力仍可使用。

### 2.2 做最小成片，不做专业剪辑器

本期“成片”定义为可审片、可再次调整的最小成品：

- 按集号、镜号顺序生成初始时间线，允许用户重排、裁剪、替换和静音镜头。
- 检查缺镜、时长、画幅和文件损坏。
- 根据 `Shot.speaker` 与 `Shot.dialogue` 绑定角色音色，生成对白 TTS。
- 允许导入授权 BGM，并设置对白轨与 BGM 轨音量。
- 根据实际音频和镜头时长生成 SRT 字幕。
- 输出带对白、BGM、字幕和渲染清单的 MP4。
- 平台内提供连续预览，并保留时间线版本。

本期不做：

- 专业多轨 NLE、转场库、特效库、调色、蒙版和关键帧动画。
- 声音克隆、声音复刻、对口型、自动音乐生成和多角色表演控制。
- 无限画布、3D 导演台和节点式工作流。
- 一键生成全部 30 集。
- 自动发布到抖音、快手、ReelShort 等平台。
- 替代剪映的专业精剪。

### 2.3 核心护城河

模型本身不是护城河。平台应围绕以下组合建立差异化：

- 角色、地点和镜头 Prompt 的一致性。
- 镜头级状态、候选、采用和返修。
- 先草片、后定稿的成本控制。
- 页面切换、刷新和服务重启后仍可恢复的任务。
- Agent 可编排，但任何付费动作都必须明确确认。
- 本地参考图默认不上传，平台内视频只使用用户明确选择的服务端资产。
- 镜头、声音和时间线都可追踪、回退、重新渲染，并随项目带走。

### 2.4 对标后的竞争位置

完成本期后，平台要和三类产品区分：

| 产品 | 强项 | 成剧不正面竞争的部分 | 成剧应守住的位置 |
|---|---|---|---|
| Flova | 通用 AI 影视工作台、时间线、Skill 社区、MCP/CLI、CapCut 草稿 | 不追求通用广告、动画和专业剪辑全覆盖 | 中文短剧结构、镜头一致性、预算与资产可核对 |
| 小云雀 | 字节模型与算力、短剧 Agent、移动端、技能与风格生态 | 不在首版追求同等模型供给和一句话全自动 | 可控生成、费用透明、本地参考图不上传、资产可带走 |
| LibTV | 无限画布、多模型、3D、智能剪辑、团队协作 | 不做无限画布、3D 和社区市场 | 线性短剧工作流、较低操作负担、按集按镜推进 |

本期目标是补齐“能成片”，不是在所有维度上追平。若只有画面拼接而没有声音和最小时间线，用户仍会回到 Flova、LibTV、小云雀或剪映，因此声音和时间线属于必做范围。

## 3. 硬边界

### 3.1 隐私边界

- 默认只使用平台已经生成并托管的角色图、地点图、镜头首帧或上一镜末帧。
- 本地参考图不得因为视频生成而自动上传。
- 生成前必须列出本次会提交给供应商的服务端资产。
- 如果未来允许主动上传本地图，必须是单独功能、单独授权和单独文案，不得复用“零上传”承诺。
- 供应商需要公网 URL 时，只能签发短时、私有、单用途 URL；不得生成永久公开链接。
- TTS 只发送当前镜头台词、说话人和音色标识，不发送本地图片或整个剧本。
- BGM 必须由用户上传并声明授权，或来自平台已确认可商用的曲库。
- 首版只允许系统预置音色，不允许声音克隆和声音复刻。

### 3.2 费用边界

- 任何视频生成或重试都必须先估算费用。
- TTS 按字符数预估，BGM 上传和本地渲染分别计入存储与计算成本。
- 批量生成必须设置最大预算。
- 没有用户确认，Agent 不得提交付费任务。
- 自动重试只允许用于明确的传输失败或供应商临时错误。
- 内容不符合预期、构图失败或用户主动否决，不属于自动免费重试。
- 预算校验必须在服务端完成，不能只依赖前端按钮状态。

### 3.3 数据边界

- API Key 只存在于服务端环境变量。
- 视频文件只存属于当前项目的数据目录。
- 下载和预览必须经过当前项目权限校验。
- 删除项目时同时删除视频、海报、字幕和渲染中间文件。
- 供应商请求日志不得记录 API Key、完整私有 URL 或本地文件路径。

### 3.4 合规边界

- 导出视频继续带 AI 标识或来源清单。
- 对真人肖像、版权角色和受保护素材保持阻塞或人工确认。
- 供应商不支持真人脸参考图的模型，不得绕过其限制。
- 平台生成资产与外部导入资产必须可区分来源。

## 4. 能力规格

### V1 · 供应商与模型能力

**Requirement**：平台以统一能力描述选择视频模型，不把某个供应商字段写死到业务层。

**Scenario V1.1**

Given 服务端已配置至少一个视频供应商
When 用户打开视频生成面板
Then 只展示当前可用供应商、模型、分辨率、时长、生成模式、是否支持首尾帧和预计单价。

**Scenario V1.2**

Given 某个模型不支持首尾帧
When 用户选择首尾帧模式
Then 该模式不可选，并说明原因，不提交请求。

**Scenario V1.3**

Given 供应商价格配置已更新
When 用户创建新任务
Then 使用新价格快照估算，旧任务仍保留原价格快照，不追溯改写历史成本。

### V2 · 单镜视频生成

**Requirement**：每个镜头可以基于已采用首帧生成一个或多个视频候选。

**Scenario V2.1**

Given 某镜头已有已采用首帧且 Prompt、画幅、时长合法
When 用户点击“生成视频”
Then 系统完成预检和费用估算，用户确认后创建持久化任务。

**Scenario V2.2**

Given 某镜头没有已采用首帧
When 用户选择图生视频
Then 系统阻止提交并提示先生成或采用首帧；文生视频模式不受此限制。

**Scenario V2.3**

Given 用户重复点击或网络重试
When 相同项目、镜头、源图哈希、参数和幂等键再次提交
Then 不创建第二个付费任务。

**Scenario V2.4**

Given 视频生成成功
When 服务端下载并校验 MP4
Then 保存文件、MIME、字节数、时长、分辨率、海报和 SHA-256，并创建候选资产。

**Scenario V2.5**

Given 供应商返回成功但文件无法读取、时长异常或超过大小限制
When 服务端校验失败
Then 任务失败，不创建不可播放的正式资产，并保留可诊断但不含敏感信息的错误。

### V3 · 候选、采用与返修

**Requirement**：视频生成结果默认是候选，不自动覆盖已采用视频。

**Scenario V3.1**

Given 某镜头已有采用视频
When 新候选生成成功
Then 原采用视频保持不变，新候选进入历史列表。

**Scenario V3.2**

Given 用户采用另一条候选
When 采用请求成功
Then 该候选成为当前镜头视频，旧文件不删除。

**Scenario V3.3**

Given 某镜头视频在质检中被标记返修
When Agent 或用户再次生成
Then 新任务关联原任务和返修原因，形成可追踪的重生成链路。

### V4 · 批量生成与恢复

**Requirement**：批量生成跨页面、刷新和服务重启后可恢复，不依赖某一个组件一直挂载。

**Scenario V4.1**

Given 用户选择第 N 集 12 个镜头
When 用户确认批量生成
Then 系统创建批次并预留预算，每个镜头拥有独立任务和独立错误。

**Scenario V4.2**

Given 批量任务正在运行
When 用户切换到角色、场次、Skill 或其他项目页面
Then 任务继续在服务端可查询，全局任务中心仍显示进度。

**Scenario V4.3**

Given 用户刷新页面
When 页面重新加载
Then 从数据库恢复任务状态；未完成任务通过供应商任务 ID 对账，不重新提交。

**Scenario V4.4**

Given 服务在任务运行期间重启
When 服务恢复
Then 有供应商任务 ID 的任务进入对账流程，不直接标记失败。

**Scenario V4.5**

Given 提交请求后网络断开，客户端不确定供应商是否收到
When 任务处于提交不确定状态
Then 标记为需要人工对账，禁止自动再次提交，避免重复扣费。

**Scenario V4.6**

Given 批次已达到最大预算
When 仍有等待任务
Then 停止提交剩余任务并显示预算耗尽，已完成任务不受影响。

### V5 · 按集时间线与粗剪

**Requirement**：系统按集号和镜号生成初始时间线，并允许用户完成最小声音与画面编排。

**Scenario V5.1**

Given 第 N 集所有镜头都有已采用视频
When 用户发起粗剪
Then 系统按 `episode`、`shot` 排序，校验时长和文件后生成 MP4、SRT 和 manifest。

**Scenario V5.2**

Given 第 N 集缺少 2 个镜头视频
When 用户尝试最终导出
Then 阻止 MP4 导出并列出缺镜；可允许用户生成“缺口预览”，但不得伪装成完整成片。

**Scenario V5.3**

Given 某镜头视频时长与 `shot.params.duration` 不一致
When 预检
Then 超出容差的镜头标为阻断；不得静默裁剪或拉长。

**Scenario V5.4**

Given 某镜头有台词
When 生成字幕
Then 使用 `speaker` 和 `dialogue` 生成 SRT，时间基于采用片段的实际时长。

**Scenario V5.5**

Given 30 集项目
When 用户选择全部导出
Then 系统不一次性启动 30 集渲染；按集排队、逐集完成，并允许用户先导出单集。

**Scenario V5.6**

Given 第 N 集已有完整初始时间线
When 用户调整镜头顺序、入点、出点、替换素材或静音
Then 系统创建新的时间线版本，不覆盖上一个可渲染版本。

**Scenario V5.7**

Given 某角色已有项目级系统音色绑定
When 系统生成对白
Then 使用 `Shot.speaker` 选择对应音色，按 `Shot.dialogue` 创建 TTS 任务，并保留逐句音频与任务记录。

**Scenario V5.8**

Given TTS 音频长度超过镜头时长
When 时间线预检
Then 标出溢出镜头，要求用户缩短台词、调整镜头或选择更短音频；不得静默加速或裁掉对白。

**Scenario V5.9**

Given 用户上传 BGM
When 时间线渲染
Then BGM 只进入 BGM 轨，默认低于对白音量；用户必须确认素材授权后才能导出。

**Scenario V5.10**

Given 用户点击最终渲染
When 请求进入服务端
Then 服务端使用不可变的 `timelineVersionId` 生成成片，不读取可能正在变化的编辑草稿。

**Scenario V5.11**

Given 已存在多个时间线版本
When 用户选择旧版本重新渲染
Then 系统按旧版本素材与参数渲染，不受当前采用视频变化影响。

**Scenario V5.12**

Given 某镜头已生成与当前台词匹配的对白 TTS
When 用户打开时间线或角色音色区域
Then 可以试听该音频，并从 0 秒重新播放

**Scenario V5.13**

Given TTS 音频时长超过对应时间线片段的有效时长
When 用户检查时间线或提交渲染
Then 界面标出具体镜头，服务端阻止生成完整成片，不静默加速或裁掉对白

**Scenario V5.14**

Given 时间线版本包含按顺序排列的镜头和台词
When 系统生成 SRT
Then 每条字幕使用镜头的实际入出点累计时间、当前台词的说话人和文本，时间不重叠

**Scenario V5.15**

Given 单集时间线版本所有镜头可渲染且声音检查通过
When 用户提交成片渲染
Then 系统使用绑定版本的视频、对白、BGM 和字幕生成 MP4、SRT 与 manifest

**Scenario V5.16**

Given 单集渲染成功
When 用户下载产物
Then MP4、SRT 和 manifest 都经过当前项目权限校验，旧版本产物不受后续草稿编辑影响

**Scenario V5.17**

Given 用户一次选择多集渲染
When 多个渲染任务进入队列
Then 单实例只执行一集，其余任务保持 queued；成功集可立即下载，失败集不阻塞后续集

### V6 · Skill / Agent 闭环

**Requirement**：Agent 能编排视频生产，但通过待确认卡片触发付费和渲染。

**Scenario V6.1**

Given 用户说“把这集先用草片模式生成”
When Agent 准备执行
Then 返回确认卡，包含模型、镜头数、总时长、分辨率、图片使用清单、预计费用和最大预算。

**Scenario V6.2**

Given 用户确认了预估 30 元、最大预算 40 元的批次
When 执行过程中发现预计费用会超过 40 元
Then 停止新增任务并要求再次确认。

**Scenario V6.3**

Given 批量生成完成
When 用户要求检查
Then Skill 检查缺镜、文件损坏、时长、画幅、黑帧和静止帧，只生成报告和待确认返修项。

**Scenario V6.4**

Given Agent 提出重试 3 个镜头
When 用户未确认
Then 不创建任务、不扣预算，只保留提案。

**Scenario V6.5**

Given 用户确认时间线与声音方案
When 渲染完成
Then Agent 可以报告成片路径、缺口、字幕、配音、时间线版本和实际费用，但不能自动发布到外部平台。

**Scenario V6.6**

Given Agent 建议为角色绑定音色或批量生成对白
When 用户未确认
Then 不创建 TTS 任务、不扣费用，只保留待确认提案。

### V7 · 外部导出

**Requirement**：新增平台内视频后，原有外部导出仍保持可用并补充已采用视频信息。

**Scenario V7.1**

Given 用户选择“即梦”导出
When 项目已有平台内视频
Then 导出包继续包含 Prompt、参考图、首帧、参数和预检，不强制附带平台视频。

**Scenario V7.2**

Given 用户选择交付包
When 平台内已有采用视频
Then manifest 记录视频资产及其来源，ZIP 是否包含视频由导出模式明确决定。

**Scenario V7.3**

Given 平台已完成时间线渲染
When 用户导出项目文件
Then 包含时间线 manifest、镜头素材映射、字幕、对白音频和最终 MP4，可重新导入平台恢复。

**Scenario V7.4**

Given 用户需要在剪映继续精剪
When 选择 CapCut 交付
Then 首阶段提供可验证的时间线清单、素材映射和逐镜音频；CapCut 私有草稿导出必须经过真实版本验证后再开放，不伪造 `.draft`。

### 5.2 为什么不使用长 HTTP 请求

视频供应商通常需要数十秒到数分钟。现有图片链路可以在请求内轮询，但视频不能沿用：

- 页面切换、网关超时或服务重启会中断请求。
- 长连接占用 Node 进程，不利于并发。
- 用户切回页面时无法知道远端任务是否已成功。

本期流程：

1. 创建本地任务并预留预算。
2. 调用供应商创建任务，立即返回。
3. 持久化供应商任务 ID。
4. 任务中心或状态接口触发按需对账。
5. 成功时下载并落盘，失败时分类处理。

### 5.3 任务对账

对账入口：

- `GET /api/video/generations` 触发当前项目的到期任务对账。
- 全局任务中心定时轮询同一接口。
- 服务启动时扫描未完成任务，有供应商任务 ID 的重新对账。
- 可选增加服务端定时 sweeper，用于页面关闭后的后台推进和通知。

对账原则：

- 有供应商任务 ID：以供应商状态为准。
- 无供应商任务 ID 且能确认请求未发出：允许重新提交。
- 无供应商任务 ID 且无法确认：标记“提交不确定”，禁止自动重试。
- 供应商成功但下载失败：保留供应商任务 ID，允许只重试下载，不重新生成。

## 6. 供应商适配层

所有供应商实现同一接口：

```ts
interface VideoProviderAdapter {
  id: string
  label: string
  capabilities(): VideoProviderCapabilities
  estimate(input: VideoGenerationInput): VideoCostEstimate
  create(input: VideoGenerationInput): Promise<ProviderTaskRef>
  poll(providerTaskId: string): Promise<ProviderTaskState>
  cancel(providerTaskId: string): Promise<void>
  normalizeResult(providerPayload: unknown): NormalizedVideoResult
}
```

能力对象至少包含：

```ts
interface VideoProviderCapabilities {
  modes: Array<"text-to-video" | "image-to-video" | "first-last-frame" | "reference-to-video">
  resolutions: string[]
  durations: number[]
  aspectRatios: string[]
  supportsAudio: boolean
  supportsSeed: boolean
  maxReferenceImages: number
  acceptsImageUrl: boolean
  acceptsImageBase64: boolean
  supportsIdempotency: boolean
}
```

适配器只负责协议转换和能力描述，不直接决定预算、权限和采用状态。

### 6.2 声音适配层

TTS 使用独立的 `SpeechProviderAdapter`：

```ts
interface SpeechProviderAdapter {
  id: string
  listVoices(): Promise<SystemVoice[]>
  estimate(input: SpeechInput): SpeechCostEstimate
  synthesize(input: SpeechInput): Promise<NormalizedSpeechResult>
  cancel(providerTaskId: string): Promise<void>
}
```

约束：

- 首版只开放供应商系统音色。
- 一个项目内每个角色最多绑定一个当前音色，历史版本仍保留原 voice id。
- TTS 必须持久化 task、字符数、费用、音色、语速和输出文件。
- 供应商支持时间戳时保存逐句或逐字时间；不支持时按句长估算并标注。
- 失败任务可以重试，但不得因网络不确定重复计费。
- 声音克隆、复刻和真人音色训练不在本期范围。

## 8. API 设计

### 8.1 能力与估算

`GET /api/video/providers`

- 返回服务端启用且已配置的适配器。
- 不返回 API Key、私有 endpoint 或供应商内部凭证。

`POST /api/video/estimate`

- 输入：项目、镜头、模式、模型、分辨率和重试假设。
- 输出：逐镜成本、批次总成本、最大预算建议和不可生成原因。
- 客户端估算只用于即时反馈，服务端重新计算后才可提交。

### 8.2 生成任务

`POST /api/video/generations`

输入包含：

- `projectId`
- `batchId`
- `shotEntityIds`
- `providerId`
- `model`
- `mode`
- `resolution`
- `duration`
- `maxBudgetMicros`
- `maxAttempts`
- `idempotencyKey`
- `confirmedAt`

行为：

1. 权限和项目归属校验。
2. 镜头、首帧、Prompt 和参数预检。
3. 服务端重新估算。
4. 预算与额度原子校验。
5. 创建批次和独立任务。
6. 提交供应商任务并持久化供应商任务 ID。

`GET /api/video/generations?projectId=...`

- 返回任务和候选资产。
- 对到期任务执行一次懒对账。

`POST /api/video/generations/:id/cancel`

- 只能取消尚未进入不可取消状态的供应商任务。
- 响应明确“本地停止”或“供应商已取消”。

`POST /api/video/generations/:id/retry`

- 仅对允许重试的错误开放。
- 必须再次经过预算检查。
- 内容失败默认转为重新编辑 Prompt，不自动重试。

### 8.3 时间线与粗剪渲染

`GET /api/timelines/:episode`

- 返回当前草稿、最新不可变版本和修改冲突版本号。

`PUT /api/timelines/:episode/draft`

- 保存当前草稿，必须携带 `expectedRevision`。
- 冲突时返回 409，不覆盖其他页面刚保存的修改。

`POST /api/timelines/:episode/versions`

- 将当前草稿固化为不可变版本。
- 校验缺镜、声音溢出、素材授权和文件哈希。

`GET /api/audio/voice-profiles?projectId=...`

- 返回项目级系统音色绑定。

`PUT /api/audio/voice-profiles/:id`

- 绑定角色与系统音色，不开放声音克隆。

`POST /api/audio/tts`

- 输入时间线中的台词片段或镜头 ID。
- 按系统音色创建独立持久化任务。
- 生成前返回字符数、费用预估和最大预算。

`POST /api/audio/bgm`

- 上传用户 BGM 并记录授权声明。
- 校验格式、大小、时长和项目权限。

`POST /api/video/renders`

- 输入项目、集号和 `timelineVersionId`。
- 服务端重新解析时间线版本、视频、对白、BGM 和字幕，不信任客户端传入的任意文件路径。
- 同一集已有运行中渲染时返回现有任务，防止重复。

`GET /api/video/renders/:id`

- 返回状态、进度、缺口和错误。

`GET /api/video/renders/:id/file`

- 权限校验后下载 MP4。

### 8.4 现有生成接口

保留 `POST /api/generations` 的图像行为。视频使用独立路由，避免把两类长任务混在一个接口里。

## 9. UI 方案

### 9.1 镜头视频卡

每个镜头在关键帧后可展开：

- 生成模式：文生视频、首帧、首尾帧、参考生成。
- 模型与分辨率。
- 预计时长和费用。
- 生成、停止、重试按钮。
- 当前采用视频、历史候选、海报和状态。
- “采用”与“返修”明确分离。

### 9.2 批量生成

沿用现有批量生图的心智：

- 按当前集筛选。
- 显示可生成、缺首帧、缺 Prompt、参数不合法数量。
- 固定低并发。
- 预算上限可见。
- 默认不自动采用。
- 任务进度进入全局任务中心。

### 9.3 全局任务中心

任务中心必须独立于当前菜单：

- 切换角色、场次、分镜、Skill、素材页不丢任务。
- 支持按项目、集号、状态和媒体类型筛选。
- 可从任务跳回对应镜头。
- 完成通知使用现有 Web Push。
- 页面刷新后从服务端恢复。

### 9.4 按集时间线

每集提供：

- 就绪度：已采用镜头数 / 总镜头数。
- 缺口清单。
- 总时长与目标时长差异。
- 字幕完整度。
- 初始按镜号排序的镜头轨。
- 重排、裁剪入出点、替换素材、静音和单镜音量。
- 草稿保存、版本历史和恢复到旧版本。
- 连续预览。

首版只有一条视频轨，不做画中画、蒙版和关键帧。

### 9.5 声音与字幕

每集提供：

- 角色与系统音色绑定。
- 按镜头显示台词、说话人、TTS 状态和音频试听。
- 单句重新生成、静音或替换。
- 对白轨与 BGM 轨音量。
- TTS 长度溢出提示。
- 字幕开关和逐句字幕预览。

声音面板必须明确区分“系统音色”与“声音克隆未开放”。

### 9.6 成片导出

- 生成 MP4、SRT 和 render manifest。
- 支持下载当前成片。
- 支持从历史时间线版本重新渲染。
- 支持导出包含时间线、素材映射和音频的项目包。

视觉上继续使用现有产品设计语言，不把视频模块做成独立应用。

## 10. Skill / Agent 工具

建议新增以下能力，沿用“工具只读或提出提案”的既有原则：

### `inspect_video_readiness(episode)`

只读返回：

- 镜头总数、已采用视频数、缺镜。
- 时长和画幅异常。
- 首帧缺失。
- 已采用候选的质检状态。
- 已绑定音色、TTS 缺失、对白溢出和 BGM 授权状态。

### `propose_video_batch(input)`

输入：

- 集号或镜头范围。
- 生成档位：草片、标准、定稿。
- 最大预算。
- 最大重试次数。
- 是否允许自动合成。

输出确认卡，不创建付费任务。

### `propose_episode_render(episode)`

只检查并生成待确认粗剪提案，用户确认后才创建渲染。

### `propose_voice_bindings(episode)`

- 根据出场角色提出系统音色绑定。
- 不创建 TTS 任务，不扣费用。

### `propose_tts_batch(episode)`

- 输入角色绑定、台词范围和最大预算。
- 返回字符数、预计费用、试听策略和待确认卡。

### `propose_timeline_update(episode, operations)`

- 允许提出重排、裁剪、替换、静音和音量调整。
- 所有操作先形成 diff 提案，用户确认后才保存新草稿或版本。

### Agent 轨迹示例

```text
你：把第 1 集先用草片模式跑一遍，控制在 40 元内。

场记：
├ 读 第 1 集分镜 9 镜
├ 读 已采用首帧 8 张，缺第 7 镜
├ 估算 H3 Lite 768P：8 镜 × 10 秒 × 1.4 次 ≈ 29.12 元
├ 读角色音色：3 个角色已绑定，1 个未绑定
├ 估算系统 TTS：186 字 ≈ 0.04-0.07 元
├ 检查 BGM：尚未上传
└ 生成待确认卡

待确认：
模型：MiniMax H3 Lite 768P
镜头：8 个可生成，第 7 镜缺首帧
声音：3 个角色使用系统音色，第 4 个角色保持静音
字幕：按对白自动生成 SRT
预算上限：40 元
失败重试：仅传输错误，最多 1 次
完成后：生成质检报告，不自动采用，不自动导出
```

## 11. 最小时间线与成片实现

### 11.1 预检

渲染前检查：

- 所有镜头属于当前项目、当前集。
- 时间线版本中的每个视频资产仍存在且属于当前项目。
- 每个有台词的镜头要么有有效 TTS，要么被用户明确设为静音。
- MP4 可读取。
- 时长与镜头参数在允许容差内。
- 画幅与目标画幅兼容。
- 文件哈希与资产记录一致。
- TTS 音频长度不超出片段可用时长；超限时阻断并定位到具体台词。
- BGM 文件有效且存在授权声明。
- 字幕开关开启时，字幕文字和说话人来自当前时间线版本。

### 11.2 FFmpeg 流程

1. `ffprobe` 读取每个视频和音频的时长、分辨率、帧率、编码和音频流。
2. 按时间线顺序对视频执行 trim、scale、fps 和统一编码。
3. 使用 concat filter 连接视频，不使用简单 concat demuxer。
4. 将每个 TTS 音频按时间线起点放入对白轨，保留少量安全间隙。
5. 将 BGM 放入独立轨道，按用户设置调整音量。
6. 对对白轨做响度标准化，按基础参数压低 BGM，避免盖住台词。
7. 使用 amix 混合并生成 AAC 音轨。
8. 根据实际片段时间与 TTS 时间生成 SRT。
9. 输出 MP4，字幕以 SRT 旁挂；平台预览负责叠加显示。
10. 写出 `render-manifest.json`，记录时间线版本、素材哈希、音色、TTS 任务、BGM 授权和渲染参数。
11. 原子移动临时文件到正式路径，避免半成品被下载。

### 11.3 时间线编辑规则

- 修改草稿不回写分镜和视频资产。
- 初始时间线由当前采用视频与镜头顺序生成。
- 每次保存草稿递增 `revision`，并使用乐观锁防止多页面覆盖。
- 用户确认渲染时，当前草稿固化为不可变 `timeline_version`。
- 旧时间线版本引用的素材即使后来未被采用，也不自动删除。
- 删除项目时统一清理时间线、TTS、BGM、渲染和中间文件。

系统依赖：

- `FFMPEG_PATH`
- `FFPROBE_PATH`

缺少依赖时，视频生成和 TTS 仍可使用；成片渲染按钮显示明确配置错误。

### 11.4 队列

- 单实例默认同时只执行 1 个成片渲染。
- 30 集不能一次排队后阻塞用户；默认按集提交。
- 渲染任务也持久化，服务重启后可标记失败并允许重试。
- 中间文件放在项目临时目录，成功后清理。

## 12. 成本控制

### 12.1 公式

```text
预计成本 =
  视频总秒数 × 当前档位单价 × 期望尝试次数
  + 额外参考图费用
  + TTS 字符数 × 音色单价
  + BGM 存储与转码估算
  + 成片渲染与存储估算
```

现有 `lib/assets/cost.ts` 的可用率模型可以复用，但价格必须改为供应商配置，不再只使用固定的 720P/1080P 单价。

### 12.2 预算状态

每个批次维护：

- `budget_limit_micros`
- `reserved_cost_micros`
- `actual_cost_micros`
- `remaining_micros`

提交前：

- 原子预留单任务最大成本。
- 任务成功或失败后结算。
- 预算不足时停止新增任务。

### 12.3 展示口径

UI 必须区分：

- 本次预估。
- 已预留。
- 已实际发生。
- 失败但供应商可能仍计费的风险。

不能把“预估 30 元”显示成“最多一定只花 30 元”，除非供应商额度、汇率和重试次数都被平台严格控制。

## 13. 错误与重试分类

| 类型 | 示例 | 自动重试 | 处理 |
|---|---|---|---|
| 配置错误 | Key 缺失、模型未开通 | 否 | 提示管理员 |
| 参数错误 | 时长不支持、画幅不支持 | 否 | 阻止提交 |
| 网络错误且确定未提交 | DNS、连接建立失败 | 最多一次 | 可重试 |
| 提交不确定 | 已发出但未收到响应 | 否 | 对账，防止重复扣费 |
| 供应商临时错误 | 429、5xx | 有条件一次 | 指数退避 |
| 内容审核失败 | 真人、版权、敏感内容 | 否 | 要求修改素材或 Prompt |
| 生成完成但下载失败 | CDN 超时 | 仅重试下载 | 不重新生成 |
| 格式校验失败 | 空 MP4、损坏文件 | 否 | 标记失败，人工检查 |
| TTS 参数错误 | 音色失效、文本为空、语速不支持 | 否 | 要求重新选择 |
| TTS 临时错误 | 429、5xx | 有条件一次 | 指数退避 |
| TTS 长度溢出 | 对白超过镜头时长 | 否 | 用户调整文本、镜头或音频 |
| BGM 授权缺失 | 用户未声明授权 | 否 | 阻止最终导出 |
| 用户否决 | 质量不满意 | 否 | 重新编辑或重新生成 |

所有错误使用稳定错误码，前端不依赖供应商原始错误字符串。

## 14. 安全与权限

- 所有视频接口继续使用项目所有者或匿名会话归属校验。
- 供应商任务 ID 不能直接暴露下载能力。
- 下载 URL 必须短时有效并绑定项目。
- 生成前检查项目、镜头和源资产归属一致。
- 批量镜头数、单任务并发和每日总时长都必须限流。
- 供应商请求体和错误日志做敏感字段清洗。
- 视频和海报下载响应包含 AI 生成说明。
- 私有素材 URL 不得写入普通应用日志。
- TTS 只发送当前镜头的必要台词，不发送整个项目。
- 音色绑定必须校验角色属于当前项目。
- BGM 上传必须记录用户授权声明和文件哈希。
- 首版不提供声音克隆入口，也不接受用户上传声音样本。

## 15. 可观测性

结构化记录：

- 创建、提交、对账、完成、失败和取消时间。
- 供应商、模型、模式、分辨率、时长。
- 预估和实际成本。
- 失败码和重试次数。
- 下载耗时、文件大小和校验结果。
- 时间线版本、镜头数、TTS 字符数、音色数量、BGM 时长和渲染耗时。

不记录：

- API Key。
- 永久素材 URL。
- 本地文件路径。
- 完整私有 Prompt 内容，除非用户主动导出诊断包。

## 16. FFmpeg 与 30 集导出

30 集不应在一个请求中同步完成。

推荐策略：

1. 用户选择单集或指定范围。
2. 每集建立独立 `video_render`。
3. 单实例一次渲染一集。
4. 前端显示逐集进度和总进度。
5. 已成功集数即时可下载。
6. 失败集数不阻塞其他集。
7. 服务重启后不保留无法恢复的 FFmpeg 子进程，任务转为可重试失败。

这样 30 集仍然是长任务，但不会表现为“页面卡住很久”或“一个失败全部重来”。

## 20. 分阶段交付

### P0 · 单供应商试点

- 复用现有任务和资产表。
- 接入一个默认视频适配器。
- 单镜、批量、取消、重试和懒对账。
- 候选与采用。
- 费用预估和最大预算。
- 全局任务中心。
- 批次预留费用、实际费用与终态自动结算。
- 视频成功/失败复用 Web Push 通知。
- 上游错误区分用户输入、供应商临时故障和限流重试。
- 批量提交最多 2 路并发，单项失败可观测且不阻断同批其他镜头。
- 真实 Key 最小付费 smoke test（需上线环境配置后执行）。

### P1 · 最小成片

- ✅ 按集生成初始时间线，支持重排、静音、裁剪和同镜历史视频替换。
- ✅ 时间线草稿、不可变版本和历史恢复。
- ✅ 项目级角色系统音色绑定。
- ✅ 单镜与按集批量对白 TTS；试听、从头重放和长度溢出检查。
- ✅ BGM 上传、授权声明和音量控制。
- ✅ 按实际时间线生成 SRT。
- ✅ FFmpeg 单集视频、对白、BGM 和字幕渲染。
- ✅ MP4、SRT 和 manifest 下载。
- ✅ 逐集持久化渲染队列，单实例串行执行，服务重启后将中断任务转为可重试失败。

### P2 · Skill / Agent

- 视频就绪检查。
- 带预算的批量提案。
- 视频质检和返修提案。
- 时间线修改提案、音色建议和 TTS 批量提案。
- 成片提案与完成通知。

### P3 · 多供应商

- Seedance 高质量适配器。
- Wan 3.0 运营兜底。
- 可灵多关键帧测试。
- 模型盲测和自动推荐。

### P4 · 精剪与互操作试点

- 对实际使用的 CapCut 版本做草稿兼容验证。
- 通过验证后再开放 CapCut 草稿导出，不能伪造私有格式。
- 支持时间线与项目包重新导入平台。
- 评估是否需要多人协作和共享资产库；无限画布、3D 和 Skill 市场仍不做。

## 21. 验收标准

### 功能

- 单镜可以生成、停止、重试和采用视频。
- 批量生成切换菜单后不中断，刷新后可恢复。
- 服务重启后不重复提交已有供应商任务。
- 每集可以查看缺口、生成初始时间线并完成重排、裁剪、替换和静音。
- 每个角色可以绑定系统音色并生成对白 TTS。
- 对白 TTS 溢出、缺失和静音状态可见。
- 用户可以上传授权 BGM，并调整对白轨与 BGM 轨音量。
- 每集可以渲染带视频、对白、BGM 和 SRT 的 MP4。
- 时间线草稿与版本可恢复，旧版本可以重新渲染。
- 30 集按集排队，可逐集下载。
- Agent 只能提出视频、TTS、时间线修改和渲染提案，确认后才执行。

### 安全

- 本地参考图不会自动上传。
- 跨项目无法读取任务、视频、海报或渲染文件。
- API Key 不进入浏览器、数据库、日志和导出包。
- 供应商临时 URL 不在日志中长期保存。
- 角色只能绑定当前项目内有效的系统音色。
- BGM 缺少授权声明时不能进入最终导出。
- 首版不存在声音克隆和声音样本上传入口。

### 成本

- 服务端重新计算预算。
- 超额批次不能继续提交。
- 预估、预留和实际成本分别可见。
- 提交不确定时不会自动重复扣费。
- TTS 按字符数和音色价格单独结算。
- 渲染预算与生成预算可分别查看。

### 质量

- 视频文件下载后必须通过 MIME、大小、可播放性和时长校验。
- 粗剪缺镜时不能伪装成完整成片。
- 时间线缺镜、缺配音或对白溢出时不能伪装成完整成片。
- 字幕时间和文字来自当前时间线版本，不使用过期分镜。
- 对白轨不能被 BGM 覆盖，混音后需要人工试听确认。
- 导出清单记录模型、来源资产和 AI 标识。
