# 创作操作系统 V2

## 背景

Flova 证明了「可复用创作方法 + Agent 执行 + 可回退项目 + 可消费交付」的产品价值。
成剧不应复制其重视频生成与完整时间线，而应把上游创作判断变成可复用、可审计、
可交付的资产。

用户已确认按以下顺序全部实现：

1. Skill 2.0：个人创作方法包。
2. 实体级评论与受控 AI 修改。
3. 跨项目角色、地点和视觉宪法资产库。
4. 剪映可消费的交付格式。
5. 分集多会话、版本分支与 MCP 只读接口。

## 全局约束

- 所有写操作必须校验项目所有权。
- 所有 Agent 写操作只产生待确认提案，用户确认后才写入正式项目数据。
- 版权、跨项目资产和项目版本都要遵守现有 SQLite 迁移方式，不在代码里散建表。
- 不读取、不上传本地图片二进制；跨项目资产只保存文本、引用和稳定标识。
- 现有六步工作流、Canon、判断日志、快照与平台导出不得回归。
- 新增后端模块必须注释「为什么、事务边界、失败行为」。

## R1 Skill 2.0：个人创作方法包

### 能力

- 用户可创建、编辑、归档个人 Skill。
- Skill 支持主文档、参考文档、阶段规则、验收标准和版本号。
- 项目可选择并固定一个 Skill 版本；更换 Skill 必须产生判断日志。
- Agent 运行时能读取当前项目采用的 Skill，并在回答中说明规则来源。
- 第一阶段不做社区市场、评分和公开发布。

### 场景

#### R1-S1 创建个人 Skill

Given 用户已登录或拥有匿名会话
When 用户提交名称、主文档和验收标准
Then 系统创建仅属于该 owner 的 Skill v1
And 同名或空内容被拒绝

#### R1-S2 保存新版本

Given 已存在个人 Skill v1
When 用户修改主文档并保存
Then 系统创建不可变的 v2，而不是覆盖 v1
And 新版本可从列表读取

#### R1-S3 项目绑定 Skill

Given 项目和一个可用 Skill 版本
When 用户把该版本应用到项目
Then 项目上下文记录 Skill id 和 version
And 切换版本写入项目判断日志
And 无效版本或跨 owner Skill 被拒绝

#### R1-S4 Agent 使用 Skill

Given 项目已绑定 Skill
When 用户询问下一步或提出创作取舍
Then Agent 状态包含 Skill 摘要
And Agent 工具能读取该摘要
And 回答上下文明确它不是全项目事实

## R2 实体级评论与受控 AI 修改

### 能力

- 评论可锚定到角色、地点、分集或镜头稳定标识。
- 评论保留原文、状态、作者和创建时间。
- Agent 可读取实体评论，并只针对该实体生成待确认修改提案。
- 不支持自由文本锚点，避免剧情修改后评论漂移。

### 场景

#### R2-S1 创建实体评论

Given 项目存在一个镜头
When 用户对该镜头提交评论
Then 评论记录保存 targetType、targetId 和正文
And 其它项目的相同 targetId 不会混入

#### R2-S2 非法锚点

Given targetType 不在允许枚举内或正文为空
When 用户提交评论
Then 返回输入错误且不写库

#### R2-S3 Agent 受限提案

Given 当前项目有一条角色评论
When Agent 调用实体修改提案工具
Then 只生成目标实体的待确认卡片
And 不直接修改项目
And 不存在的实体被拒绝

## R3 跨项目资产库

### 能力

- 用户可把角色的文本资产保存到跨项目库。
- 用户可把地点和视觉宪法保存到跨项目库。
- 资产记录来源项目、类型、名称、内容快照和版本。
- 同 owner 可按类型和名称检索；跨 owner 不可见。
- 本地图片路径或图片二进制不进入跨项目库。

### 场景

#### R3-S1 保存角色

Given 当前项目有角色
When 用户选择保存到资产库
Then 系统对同 owner 创建一个资产记录
And 内容包含角色文本字段和来源项目 id
And 不包含任何图片二进制

#### R3-S2 重名更新

Given 同 owner 已有同名同类型资产
When 用户再次保存
Then 更新该资产内容并递增版本
And 不产生两条同名活动记录

#### R3-S3 隔离

Given 另一 owner 的资产
When 当前 owner 查询资产库
Then 结果不包含另一 owner 的记录

## R4 剪映可消费交付

### 能力

- 平台交付目标新增 `jianying`。
- 生成镜头顺序清单、台词与字幕清单、素材映射和执行说明。
- 提供稳定的 `chengju.jianying-delivery` manifest。
- 第一阶段不生成无法验证版本的私有二进制草稿；后续可在同一适配器内替换。
- 预检继续沿用通用平台规则。

### 场景

#### R4-S1 目标识别

Given 导出目标为 `jianying`
When 构建平台导出包
Then 返回剪映执行清单、台词字幕表和 manifest
And 每镜包含顺序、时长、画幅、首帧路径和台词

#### R4-S2 空台词

Given 镜头没有台词
When 生成字幕表
Then 不产生伪造字幕行
And 清单仍保留该镜的视频占位

#### R4-S3 选择入口

Given 用户打开导出菜单
When 查看目标平台
Then 可看到「剪映」选项

## R5 多会话、版本分支与 MCP 只读接口

### 能力

- 项目可创建多个 Agent 会话，每个会话有稳定 id、标题和消息文本。
- 会话共享同一项目和 Skill，不复制项目状态。
- 用户可从已有快照创建版本分支记录，记录基线快照和说明。
- 提供 MCP 只读发现接口，列出项目、上下文、Skill、快照和交付能力。
- 外部读取必须使用现有身份校验，不暴露本地媒体路径、私钥或其它 owner 数据。
- 第一阶段不开放远程写操作。

### 场景

#### R5-S1 多会话隔离

Given 同一项目已有两个 Agent 会话
When 读取其中一个会话
Then 只能看到该会话消息
And 两个会话都能读取同一个项目 Skill

#### R5-S2 版本分支

Given 项目存在快照
When 用户基于该快照创建分支
Then 保存分支名称、基线快照和创建者
And 不存在的快照被拒绝

#### R5-S3 MCP 只读清单

Given 已认证 owner 请求 MCP 能力清单
When 服务端聚合数据
Then 只返回该 owner 的项目摘要和能力声明
And 不返回图片存储路径、API Key 或会话 Cookie

## 不在本轮范围

- 直接调用即梦、可灵、剪映的私有 API。
- 图生视频、自动成片和完整时间线。
- Skill 社区、评分、付费和公开分享。
- 外部 Agent 直接写项目。

## 验收门禁

- 每个 Requirement 至少有一条从失败开始的自动化测试。
- 全量 `npm test` 通过。
- TypeScript 检查和 `npm run build` 通过。
- 关键 UI 在 1440 和 390 宽度完成真实截图检查。
- 更新 README、APP.md 或对应规格中的实际状态，禁止把计划写成已上线。
