# Production Hardening P6

> 本轮解决整集外部视频逐个导入的成本，批量回传仍复用现有镜头视频资产事实。

## R1 文件名映射

Given 用户选择多个 MP4
Then 系统从文件名解析集号与镜号
And 支持以下无歧义格式：

- `E01-S02.mp4`
- `EP01_SHOT02.mp4`
- `1-2.mp4`
- `第1集第2镜.mp4`

无法解析、项目中不存在、同一镜头匹配多个文件、非 MP4 或超过 80MB 的文件不得上传。

## R2 导入预览

Given 文件已完成本地匹配
Then 界面显示“文件名 → 第几集第几镜”的预览
And 显示未匹配或冲突原因
And 只有用户确认后才提交
And 所有匹配文件通过一次批量 API 请求提交。

## R3 服务端批量导入

- 一次请求最多 20 个文件。
- owner、项目、镜头和 mapping 索引全部校验。
- 每个成功项写入同一 generation task/asset 体系并自动采用。
- 部分失败必须返回成功资产与逐项错误，不伪装全部成功。
- 不调用模型、不扣额度。

## 浏览器验收

- E2E 选择两个符合命名规则的 MP4。
- 预览显示两条镜头映射。
- 确认后两个镜头均出现外部视频候选。
- 桌面与 390px 截图无溢出。

## 非目标

- 不支持无命名规则的自动猜测。
- 不上传图片、音频或项目包。
- 不改变单个导入入口与现有视频版本规则。
