# 原生 App 视觉壳

## 1. 目标

先交付一个可运行的 Expo / React Native 原生视觉壳，用真实移动端布局确认原生 App 的信息架构、品牌气质和页面层级。

本轮不连接项目、Agent、生成任务、支付或账号 API。页面使用明确标注的演示数据，只用于视觉与导航验收。

## 2. 硬边界

- 不使用 WebView，不把现有 Web 工作台嵌入 App。
- 不新增第二套品牌色或导航命名。
- Agent 是唯一主屏；项目、任务、账户通过原生栈页进入，不设置底部四入口工作台导航。
- Agent 页必须持续显示当前项目、AI 场记上下文和下一步，不能退化成欢迎语聊天页。
- 所有可交互目标至少 44pt。
- 页面适配 iOS 和 Android 安全区。
- Web 只作为开发截图预览，不是发布目标。

## 3. 能力与场景

### R1 App 主导航

Given 用户启动 App
When 原生导航加载完成
Then 默认进入 Agent 主屏；项目从顶部项目胶囊进入，账户从右上角进入，任务从运行状态进入。

并且 App 不使用 Web 式底部四入口工作台导航。

### R2 Agent 首页

Given 当前项目为夜港来信第 3 集
When 用户打开 Agent 首页
Then 第一屏能看到当前项目胶囊、当前场次、一句创作问题、场景画面、对话/创作切换、快速灵感和输入区。

并且首页不展示六步工作台、完整项目进度或大规模任务表。

### R3 项目页

Given 用户有多个项目
When 打开项目页
Then 当前项目置顶，其他项目显示最近更新、集数和完成度。

### R4 任务页

Given 存在待确认关键帧
When 打开任务页
Then 首要位置显示审片卡和采用/退回动作，运行与失败任务在下方可扫。

### R5 我的页

Given 用户为匿名或未同步状态
When 打开我的页
Then 显示账号同步、额度、通知、设备、隐私与订阅入口，不伪造已登录状态。

### R6 审片

Given 某镜头有多个关键帧版本
When 打开审片页
Then 以大画幅显示当前版本，提供版本切换、采用和退回动作。

## 4. 验证

- TypeScript 类型检查通过。
- 演示数据契约测试通过。
- Web 开发渲染用于截图验收，375×812 和 390×844 无横向溢出。
- 真实原生构建留到下一阶段，本轮不以 Web 预览代替 App Store 产物。
