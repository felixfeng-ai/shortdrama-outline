# 原生 App · Agent 建议写回

## 1. 目标

让用户在 App 内确认 shot-edit 建议后，真正修改同一项目的 `shots` 快照。App 与 Web 共用同一条项目、快照和版本链，不维护第二份移动端数据。

## 2. 硬边界

- 只允许修改当前会话有权限的项目。
- 只能修改已有镜头的 `prompt` 或 `action`。
- 写回必须携带 Agent 读取时的 `shots` 快照 ID。
- 若最新 `shots` 快照已经变化，返回 409，不覆盖 Web 或其他设备的更新。
- 不修改镜头身份、镜号、角色、台词、参数或其他镜头。
- 写回不调用模型、不扣模型额度。
- 提案在成功写入前只能显示“待确认”，不能提前显示已保存。

## 3. 能力与场景

### R1 版本化写回

Given Agent 基于某个 `shots` 快照生成建议
When 用户点击写入
Then 服务端核对最新快照 ID，匹配后创建下一版 `shots` 快照。

Given 最新快照已变化
Then 返回 409，并保留原建议供用户重新读取。

### R2 字段约束

Given `shot-edit` 建议
When 服务端执行
Then 只更新目标镜头的 `prompt` 或 `action`，其余字段和其他镜头保持不变。

### R3 Web/App 共用

Given App 成功写入一版
Then Web 的 `/api/snapshots?projectId&kind=shots` 能立即读到该版本。

Given Web 写入一版
Then App 下一次同步会读到新的镜头数和场次上下文。

### R4 移动端状态

Given 用户确认建议
Then 按钮进入写入中，成功后显示新版本号。

Given 写入失败或版本冲突
Then 保留建议与输入，显示原因并允许重试或返回。

## 4. 验证

- 纯函数测试覆盖字段修改、非法输入与快照版本递增。
- 冲突测试覆盖旧快照 ID 被拒绝。
- 移动端 API 与状态测试覆盖写入中、成功、失败和重试。
- 根项目与移动端全量测试、类型检查和构建通过。
- 使用临时数据库验证 App 写入后 Web 快照接口可读到新版本。
