# 生成成本护栏

> 状态：已实现，等待产品验收  
> 日期：2026-11-04  
> 优先级：P1，成本可预期

## 1. 目标

在用户点击付费生成动作前，明确显示本次预计消耗的额度单位、当前剩余额度，
以及是否足够完成。额度不足时提前阻止请求，不把用户送到 429 才说明原因。

## 2. 口径

- 六步主生成动作统一从模型价格表取单位数。
- 分集按实际批次计价，30 集是 9 单位而不是固定 3 单位。
- 两版对比按两次普通生成计价。
- 额度未知时只显示本步单位，不把“读取中”说成“足够”或“不足”。
- 额度读取失败不阻断流程，由服务端继续做最终校验。

## 3. UI

- 主生成按钮旁显示：`本步 N 单位 · 剩余 M`。
- 额度不足时显示：`额度不足（差 X）`，并禁用该生成按钮。
- 两版对比和第一集双方向同样遵守额度检查。
- 不弹新的全屏确认层，不改变 Signal Desk 工作台结构。
- 手机端提示可换行，不挤出按钮或导致横向滚动。

## 4. 失败与兼容

- 旧项目不需要迁移。
- 额度接口失败时保持现有生成入口可用。
- 服务端 `chargeQuota` 仍是最终权威，不信任客户端预估。
- 模型内部 JSON 重试属于同一次请求，不重复扣额度。

## 5. 验收

1. 六个主生成动作都显示本步单位与剩余额度。
2. 分集单位随 10/30/60 集变化。
3. 剩余不足时按钮禁用，并显示差多少。
4. 额度未知时不误判不足。
5. 全量测试、TypeScript、生产构建通过。
6. 桌面 1440 与手机 390 真实页面无溢出。

  第一集双方向接入本步单位、剩余额度与差额提示。

  生成按钮禁用，请求不会发出。
