# 原生 App 整集草片优先工作流

## 目标

在现有轻量 Agent 首页之外增加一个原生工作流：先用低成本 480P 草片检查整集节奏，再挑选需要定稿的镜头。App 只负责选镜、提交、看批次进度和做轻量确认，不承担 Web 时间线剪辑。

## 能力点

### R1 按集汇总镜头与准备率

- 用户进入整集草片页后，默认选中当前 Agent 场次所在集。
- 页面支持 `projectId` 深链；目标项目存在时先切换项目，再从该项目真实分集里选当前集。
- 分集选择只展示真实存在的集，并显示该集镜头数与首帧准备率。
- 镜头列表必须显示镜头号、场景、首帧状态、最近视频任务状态。
- 用户可以在“整集”和“仅可生成”之间切换，查看全部镜头或缺首帧镜头。

### R2 缺首帧镜头逐镜阻断

- 缺少已采用首帧的镜头保留在清单中，并显示明确原因。
- 提交时允许把这些镜头交给现有批量接口逐镜校验，单个镜头阻断不能让同批其他镜头失败。
- 没有可生成镜头时主按钮禁用，不创建空批次。

### R3 低成本整集草片提交

- 草片固定使用 `MiniMax-H3-Lite`、`480P`、每镜 5 秒，费用由公开视频能力实时计算。
- 提交前展示可生成镜头数、缺首帧数、预计费用和本次预算上限。
- 预算上限等于可生成镜头的服务端同口径估算，不允许客户端伪造成本。
- 每次提交生成稳定幂等键；重复点击不能产生重复批次。

### R4 批次进度与审片入口

- 提交成功后保留批次回执，显示草片任务数、批次状态和独立失败数。
- 页面可刷新当前项目任务，并进入现有任务中心按批次审片。
- 不新增手机端时间线或专业剪辑器。

### R5 草片定稿标记

- 用户可以在草片页把镜头标记为“需要定稿”。
- 标记写入现有镜头批注，正文使用固定可识别前缀，Web 和其他设备读取同一项目批注即可看到。
- 取消标记时只处理对应的开放定稿批注，不影响普通审片批注。
- 已标记镜头明确说明后续以 768P/2K 出定稿，本轮不自动创建高价任务。

## 页面与视觉

- 首页保持现有轻量 Agent 主结构，仅在现有工具行增加一个“整集草片”入口。
- 草片页沿用暖白画布、发丝线、原生栈页、44pt 触控目标和现有 `ScreenHeader` / `Panel`。
- 页面主角是当前集的镜头准备状态，主操作是确认预算并生成草片；分集和筛选只做次级控制。
- 390、375 和最小支持宽度不得横向溢出；需要覆盖加载、空、失败、部分阻断和已提交状态。

## 验收

- 每个能力点先有失败测试，再实现到通过。
- App 全量测试、类型检查、Expo Web 导出和商店检查通过。
- Web/API 全量测试、类型检查和生产构建通过。
- 使用真实项目数据完成 390/375 截图验收。
- 未实际发起付费草片时，界面与交付说明必须明确标注为“未提交付费任务”。
