# 长剧集生成断点续跑

> 目标：分集或分镜在批次中途失败后，下一次请求能从已完成批次继续。

## 1. 能力

- 每个项目分别保存分集、分镜各一个生成 checkpoint。
- checkpoint 记录输入签名、下一批游标、已生成内容和稳定 stamp。
- 只有输入签名一致且用户请求续跑时才复用。
- 每批成功后更新 checkpoint；全部成功后删除。
- 失败、取消或连接中断时保留 checkpoint。

## 2. 硬边界

- checkpoint 不代替正式快照，不进入版本血缘。
- 上游人物、大纲、场次等输入变化后，旧 checkpoint 自动失效。
- 不跨项目、不跨生成类型复用。
- checkpoint 内容只存在服务端数据目录。
- 用户主动“重新生成”时不带续跑参数，旧 checkpoint 被新任务覆盖。

## 3. 场景

### T1 分集续跑

**Scenario T1.1**
Given 60 集生成已完成前 20 集
When 用户重试并要求续跑
Then 从第 21 集开始，不重复调用前两批。

### T2 分镜续跑

**Scenario T2.1**
Given 分镜已完成前 16 场
When 用户重试并要求续跑
Then 从第 17 场开始，并保留原镜号与 entityId。

### T3 输入失效

**Scenario T3.1**
Given checkpoint 对应旧人物或旧场次
When 当前输入签名不一致
Then 忽略旧 checkpoint，从头生成。

## 4. 验收

- checkpoint 存取、签名失效、项目隔离和类型隔离均有测试。
- 分集/分镜每批完成即保存，成功后清理。
- 前端失败后下一次点击自动带续跑标记。
- 全量测试、类型检查、生产构建和浏览器状态验收通过。
