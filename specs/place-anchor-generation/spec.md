# 地点锚点补建与场景图生成

## 目标

让第 5 步「生成场景」中的地点资产与第 4 步角色定妆保持同一套工作方式：

- 场次里出现、但地点清单遗漏的地点，可以由用户直接补建视觉锚点。
- 已有锚点的地点可以直接用平台图像服务生成空场景定妆图。
- 新生成的场景图进入项目资产链，既作为该地点的后续重生成参考，也作为相关镜头首帧的地点一致性参考。

## R1 · 补建缺失地点锚点

### 场景 R1.1 · 看见真实缺口

Given 场次地点为「外门弟子通铺外」，但地点清单中没有同名地点
When 用户进入第 5 步
Then 标题显示「已建立 N 个地点」，预警显示「缺少 1 个」，并点名「外门弟子通铺外」

### 场景 R1.2 · 补建入口

Given 存在缺失地点
When 用户查看该缺失项
Then 每项都有「补建锚点」操作，点击后展开名称已预填的地点表单

### 场景 R1.3 · 保存锚点

Given 补建表单中至少填写了空间结构、陈设道具、光线条件或色调氛围之一
When 用户点击保存
Then 系统按固定字段顺序编译地点锚点，将该地点加入地点清单，预警移除，并保留其他地点不变

### 场景 R1.4 · 不制造空锚点

Given 补建表单四个视觉字段都为空
Then 保存按钮不可用，用户不会得到一个仍然没有内容的地点条目

## R2 · 地点文生图

### 场景 R2.1 · 地点卡提供场景图生成

Given 一个地点已有非空锚点
When 用户查看地点卡
Then 可以看到「生成场景图」入口、生成状态、历史版本、采用、下载和失败重试，交互与角色定妆图一致

### 场景 R2.2 · 场景图提示词

Given 地点锚点包含空间、陈设、光线和色调
When 发起场景图生成
Then 提示词由地点锚点派生，并明确要求空场景、无人物、广角建立镜头；项目视觉宪法同时进入提示词

### 场景 R2.3 · 资产隔离

Given 同一项目有多个地点
When 某个地点生成场景图
Then 任务和图片按地点隔离，采用一版不会覆盖其他地点的图片

### 场景 R2.4 · 本地参考图边界

Given 用户为地点挂了本地场景图
When 使用云端生成场景图
Then 本地图像素仍然不会上传；本地场景图和云端生成图在界面中明确区分

## R3 · 场景图进入一致性链

### 场景 R3.1 · 地点重生成参考

Given 某地点已经采用过一版云端场景图
When 用户重新生成该地点
Then 已采用场景图作为地点空间参考，优先保持建筑结构、陈设、光线和色调

### 场景 R3.2 · 镜头生成参考

Given 某镜头地点已有采用的云端场景图
When 生成该镜头首帧
Then 场景图作为地点参考加入现有最多 3 张参考图的预算；角色图优先，剩余槽位给地点图

### 场景 R3.3 · 无场景图不改变旧行为

Given 地点没有云端场景图
When 生成镜头首帧
Then 参考图选择与当前行为一致，不报错

## R4 · 任务与通知

### 场景 R4.1 · 任务中心

Given 地点图任务成功或失败
When 用户查看生成任务中心
Then 任务显示为「地点 · 地点名」，地点任务重试使用 16:9 横图

### 场景 R4.2 · 推送

Given 已开启生成通知
When 地点图任务完成或失败
Then 通知文案使用「场景图」，点击回到第 5 步

## 非目标

- 不让场景图包含人物，也不把角色定妆图用于地点生成。
- 不把本地场景图像素上传到服务端。
- 不新增独立图像供应商或新的计费体系。
- 不在本阶段自动修复已有镜头提示词；补建锚点后由用户决定是否重新生成受影响镜头。
