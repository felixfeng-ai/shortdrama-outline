# 原生 App · 现场连续性 2.0 与视频审片 2.0

## 目标

在现有轻量 Agent、任务中心和审片页内补齐两个高频现场闭环：

1. 现场拍摄时记录 Take、好镜、语音备注和返修队列。
2. 视频审片时按时间码批注、截取当前帧、执行通过/返修/定稿，并检查画幅与字幕轨。

不新增完整场记后台、团队权限、审批链或 Web 时间线编辑器。

## 能力点

### R1 现场 Take 记录

- 当前镜头可以记录多条 Take，正文包含备注、连续性检查摘要和问题数量。
- 检查完成后可直接把当前结果记成一条 Take。
- 每条 Take 可以标记为“好镜”，同一项目同一镜头最多一条好镜。
- Take 记录通过现有项目账号隔离持久化，Web 和其他设备可读取。
- 照片仍只用于本次连续性检查，不写入 Take 或生成资产。

### R2 语音备注与返修队列

- Take 备注支持系统语音识别，转写文本进入同一输入框，仍可继续手改。
- 连续性检查发现偏差时，可以一键写入镜头返修批注。
- App 提供项目级返修队列，按集/镜头读取开放退回与定稿记录。
- 返修项可以标记已处理，并回到对应镜头审片。

### R3 视频时间码批注

- 视频审片页显示当前播放时间码。
- 新批注自动附带当前时间码；历史批注显示时间码。
- 点击历史批注时间码可以回到视频对应位置。
- 批注仍通过现有项目批注接口按账号隔离保存。

### R4 截图标记与逐镜确认

- 用户可以从当前视频画面截取一帧并在提交前查看。
- 截图仅随本次提交预览；服务端保存时间码和“已标记画面”元数据，不上传完整视频帧。
- 视频主操作使用“通过并采用”，返修使用“退回并说明”。
- 镜头可以额外标记“定稿”，审片页明确显示待确认、返修中、已通过或已定稿。

### R5 画幅与字幕轨检查

- 审片资产读取真实宽高，并和镜头目标画幅比较。
- 已知宽高时显示匹配或不匹配；未知时明确显示“尺寸未记录”。
- 原生播放器暴露内嵌字幕轨数量，审片页显示检测结果，不伪造字幕内容审核。

## 页面与交互

- 现场连续性页保持“现场照片 + Canon 检查”为唯一主角。
- 检查结果下方增加 Take 记录；语音、保存和好镜是次级动作。
- 返修队列使用独立原生栈页面，每行只显示问题、镜头和状态。
- 视频审片页保持视频为唯一主角；时间码批注和检查信息位于画面下方。
- 390 和 375 宽度无横向溢出，触控目标至少 44pt。

## 验收

- 每个能力点先写失败测试，再实现到通过。
- Web 端覆盖批注元数据、Take 持久化、好镜唯一性和账号隔离。
- App 端覆盖客户端映射、审片页接线、语音备注和返修队列。
- App/Web 全量测试、TypeScript、Expo 导出和 Web 生产构建通过。
- 使用真实 Expo Web 完成 390/375 截图验收；原生视频截图和语音权限仍需真机确认。
