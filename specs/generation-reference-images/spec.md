# 生成关键帧一致性参考

> 目标：让同一项目中已采用的角色关键帧成为后续定妆与镜头首帧的身份和风格参考。

## 1. 能力

- 镜头生成时，按出场角色自动带入当前项目已采用的角色关键帧。
- 角色重新生成时，优先带入该角色自己的已采用图作为身份参考。
- 新角色生成时，可带入最多两张其他已采用角色图，但只作为画风、光线和质感参考。
- 单次最多发送三张项目关键帧。

## 2. 硬边界

- 只使用当前项目、当前 owner 下已经采用并由平台生成的图片。
- 用户本地图库原图、镜头原始上传文件和素材目录内容不得上传。
- 没有可用参考图时回退现有文生图链路，不阻断生成。
- 任一参考图缺失或读取失败时跳过该图；实际发送数量必须在结果中返回。
- 参考图只传服务端数据地址，不把 API Key 或文件路径返回前端。

## 3. 场景

### T1 镜头身份一致性

**Scenario T1.1**
Given 镜头出场角色中至少一人已有采用的关键帧
When 用户生成该镜头首帧
Then 服务端按出场顺序带入最多三名角色的采用图，并在提示词中标记身份参考。

### T2 角色风格一致性

**Scenario T2.1**
Given 当前角色已有采用图
When 用户重新生成该角色定妆
Then 自己的采用图排在第一张作为身份参考，其他采用图最多两张只作风格参考。

**Scenario T2.2**
Given 当前角色还没有采用图，但项目内其他角色有采用图
When 用户生成当前角色定妆
Then 最多带入两张其他角色图，并明确禁止复制其身份与服装。

### T3 回退与透明

**Scenario T3.1**
Given 项目内没有已采用角色图
When 用户生成关键帧
Then 仍走现有通义文生图链路。

**Scenario T3.2**
Given 已采用图的文件缺失
When 服务端准备参考图
Then 跳过缺失文件，不因参考图失败而阻断生成。

## 4. 验收

- 参考图选择为纯函数并有单元测试。
- 通义多图编辑请求包含 1-3 张图、同步结果解析和原有错误脱敏。
- 路由与界面返回并展示实际参考图数量。
- 全量测试、类型检查、生产构建和本地浏览器验收通过。
