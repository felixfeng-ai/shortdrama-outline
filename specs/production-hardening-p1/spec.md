# Production Hardening P1

> 本轮只把已有的动态分镜能力接成用户可感知、可验证的真实链路，不新增第二套进度，也不调用付费模型。

## R1 示例项目自带可播放动态分镜

Given 用户从空工作台载入完整示例
When 示例项目创建完成
Then 至少 5 个正式镜头各自拥有一张已采用真实首帧
And 动态分镜计划为 `ready`，总时长 30～45 秒
And 资产、任务与文件都写入现有项目事实
And 重复载入不重复创建项目、任务或资产
And 不调用模型、不扣额度

## R2 工作台入口使用真实预览事实

Given 当前项目已拥有 `ready` 动态分镜
When 用户查看项目总览
Then 总览出现“播放动态分镜”入口，并显示真实秒数与镜数
And 素材不足时不显示播放入口，避免把用户带进新的假进度

## R3 播放器浏览器验收

Given 隔离数据库与本地媒体目录
When 执行核心浏览器 E2E
Then 示例项目可打开 30 秒动态分镜
And 播放进度会真实前进，上一镜/下一镜可切换
And 1440px 与 390px 均无横向溢出或控制台错误
And 无素材项目明确显示 `insufficient` 与“还差多少秒”状态

## 非目标

- 不新增漫剧能力。
- 不在本轮重做播放器视觉。
- 不把 TTS、BGM、MP4 导出或真实付费供应商加入本轮 CI。
- 不复制快速试片、生成任务或项目进度的数据结构。

## 验收

- 示例项目集成测试覆盖真实资产、30 秒 ready 与幂等。
- 工作台入口测试只允许 `ready` 状态出现。
- 浏览器 E2E 覆盖 ready、insufficient、桌面与移动端。
- `npm test`、`npx tsc --noEmit`、`npm run build`、`npm run test:e2e:core` 通过。
