# Canon 事实与冲突检查

## 目标

为长剧集建立可查询、可审计的连续性事实，先覆盖角色认知、人物关系、地点和道具状态，并把冲突暴露给用户与 AI 场记。

## 能力点

### C1 Canon 数据模型

- `canon_entities` 保存项目内实体：角色、地点、道具、关系。
- `canon_facts` 保存实体在某一集数区间内的事实值和锁定状态。
- 实体与事实随项目删除级联清理。
- 迁移通过 `schema_migrations` 执行。

### C2 事实写入

- 创建事实时可以自动创建同名实体。
- 实体类型只允许 `character / place / prop / relationship`。
- 字段、值不能为空。
- 有效集数范围为 1–120，且开始集不得大于结束集。
- 同一实体、字段、值、区间重复写入时返回已有事实，避免重复数据。

### C3 冲突审计

- 同一实体、同一字段在重叠集数区间内出现不同值时，标记为 `error`。
- 事实本身集数区间非法时，标记为 `error`。
- 同一实体、字段、值但不能合并为连续区间时，给出 `warning`。
- `locked` 事实参与冲突检查，但锁定本身不消除冲突。
- 审计只读，不自动修改或删除事实。

### C4 API 与 Agent

- `GET /api/projects/[id]/canon` 返回实体、事实和冲突。
- `POST /api/projects/[id]/canon` 创建事实。
- Agent 状态包含当前 Canon 冲突，新增只读工具 `audit_canon`。
- Agent 提出创作决策前应读取 Canon 冲突，但不能自动修复。

### C5 UI

- 项目状态区新增“Canon”入口。
- 显示实体数量、事实数量和错误/提醒数量。
- 冲突显示涉及实体、字段、集数范围和冲突值。
- 当前版本先做只读审计，不提供图形化编辑表单。

## 不在本阶段

- 从全文自动抽取 Canon
- 修改/删除事实
- 决策落库前强制阻断
- 关系图谱可视化
- 多人审批

## 验收场景

1. Given 一个角色在第 1–10 集知道真相，When 写入第 5–8 集不知道真相，Then 审计报 error。
2. Given 不重叠区间有两个不同状态，When 审计，Then 不报冲突。
3. Given 开始集大于结束集，When 写入或审计，Then 返回校验错误。
4. Given 重复事实，When 再次写入，Then 返回已有记录且不产生重复。
5. Given 另一个 owner，When 读取 Canon，Then 返回 403。
6. Given Canon 有冲突，When Agent 调 `audit_canon`，Then 返回带实体和集数范围的简短结论。
