# 原生 App 视频审片播放与下载

## 目标

修复视频生成后在审片页显示 0 秒、无法播放，以及下载失败时错误使用图片文案的问题。

## 能力点

### R1 视频资产支持分段传输

- `/api/generated-assets/:id` 对视频和音频返回 `Accept-Ranges: bytes`。
- 收到单段 `Range: bytes=start-end` 时返回 `206 Partial Content`、正确的 `Content-Range` 和切片内容。
- 越界 Range 返回 `416` 和 `Content-Range: bytes */总长度`。
- `HEAD` 请求返回相同媒体类型、长度和缓存头，但响应体为空。
- CORS 允许 `Range` 请求头，Expo Web 预览也能拖动视频。

### R2 原生播放器显式识别 MP4

- 视频资产 URL 没有 `.mp4` 扩展名时，App 仍显式传入 `contentType: progressive`。
- 图片和视频使用各自的媒体源构造，不把视频专用字段传给图片组件。

### R3 下载文案与错误状态

- 下载失败文案按 MIME 显示“视频下载失败”“音频下载失败”或“图片下载失败”。
- HTTP 失败保留状态码；401/403 提示重新登录，404 提示文件不存在，其余状态显示明确状态码。
- 原生系统分享弹窗按类型显示“保存视频”“保存音频”或“保存图片”。

## 验收

- Web 资产接口测试覆盖 200、206、416 和 HEAD。
- App 纯逻辑测试覆盖视频媒体源和下载文案。
- App/Web 全量测试、类型检查和生产构建通过。
- 使用真实 5 秒 MP4 验证 Range 响应长度和时长，不发送付费生成任务。
