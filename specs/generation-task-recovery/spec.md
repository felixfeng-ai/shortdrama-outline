# 生成任务恢复

> 目标：服务重启、浏览器刷新或请求异常后，遗留任务不能永久显示为“运行中”。

## 1. 能力

- 读取任务列表时自动识别超过安全时限的 queued / running 任务。
- 超时任务转为 failed，并写入可读、可重试的恢复原因。
- 尚未超时的活跃任务继续保留 running，不误判。
- 已完成、失败、取消任务不重复处理。
- 关键帧卡看到未结束任务时禁止重复提交。

## 2. 硬边界

- 安全时限必须长于服务端生成接口最大执行时间。
- 只处理当前项目、当前 owner 的任务。
- 超时恢复不改动历史资产和已采用关键帧。
- 不承诺取消通义远端任务；恢复文案要明确远端可能仍会完成。
- 恢复动作不扣额度、不自动发起重试。

## 3. 场景

### T1 超时任务恢复

**Scenario T1.1**
Given 一个 running 任务开始超过安全时限
When 用户刷新任务列表
Then 任务变为 failed，并显示“上次生成等待已中断，可重试”。

### T2 活跃任务保护

**Scenario T2.1**
Given 一个 running 任务开始时间仍在安全时限内
When 用户刷新任务列表
Then 任务保持 running，不显示重试按钮。

### T3 防重复提交

**Scenario T3.1**
Given 当前关键帧目标已有 queued 或 running 任务
When 用户刷新页面后查看生成按钮
Then 按钮不可再次提交，并提示任务可能仍在运行。

## 4. 验收

- 恢复阈值、项目隔离、终态不变均有单元测试。
- GET 任务接口返回前执行恢复。
- 全量测试、类型检查、生产构建和浏览器刷新验收通过。
