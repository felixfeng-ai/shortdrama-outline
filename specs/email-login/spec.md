# 邮箱验证码登录

## 目标

为个人开发者环境提供不依赖短信供应商的正式登录方式。用户可以使用邮箱验证码登录、跨设备找回项目，并继续使用现有项目归属、会话轮换和设备管理能力。

## 能力点

### E1 邮箱规范化与用户身份

- 邮箱去除首尾空格并转为小写。
- 只接受包含本地部分、域名和有效后缀的邮箱，最长 254 字符。
- 新邮箱首次登录时创建用户；已有邮箱直接登录。
- 邮箱用户与手机号用户共用 `user_*` 用户、会话和项目归属体系。
- 现有手机号用户及其项目不能因数据库升级丢失。

### E2 邮箱验证码签发

- 生成 6 位数字验证码，5 分钟内有效，只保存带服务端密钥的哈希。
- 同一邮箱 60 秒内只能发送一次，每小时最多发送 5 次。
- 验证码最多尝试 5 次，成功后立即标记已使用。
- 请求验证码不暴露邮箱是否已注册。
- 开发环境仅在 localhost/127.0.0.1 且 `AUTH_ALLOW_DEV_CODE=1` 时返回 `devCode`。
- 生产环境缺少 SMTP 配置时返回明确的 `503`，不能伪造发送成功。
- 生产环境 SMTP 发送失败时返回 `502`，并清理本次未送达的验证码记录。

### E3 邮箱验证码校验与会话

- 正确验证码创建 Web HttpOnly 会话；App 调用返回 Access/Refresh Token。
- 首次邮箱登录只认领当前匿名会话的项目和推送订阅。
- 错误、过期、重复使用和超过尝试次数的验证码必须被拒绝。
- 邮箱登录与手机号登录产生相同形态的会话，不新增第二套鉴权协议。

### E4 Web 登录体验

- 独立 `/login` 页面默认展示邮箱登录。
- 登录步骤为邮箱地址、验证码两步，包含发送倒计时、错误恢复、修改邮箱和返回工作台。
- 账号页优先显示邮箱；没有邮箱的既有手机号账号继续显示手机号。
- 顶栏账号入口不再假定用户一定有手机号。
- 手机号 API 保留兼容，但 Web 登录页不在短信通道未配置时把手机号作为默认入口。

### E5 配置与运维

支持以下 SMTP 环境变量：

- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_SECURE`
- `SMTP_USER`
- `SMTP_PASS`
- `AUTH_EMAIL_FROM`

邮件正文只包含验证码、有效期和登录用途，不包含用户项目内容、提示词或内部路径。

## 不在本次范围

- 微信登录
- 邮箱登录链接
- 手机号与邮箱自动合并
- 邮件模板可视化后台
- 多语言邮件

## 验收场景

1. Given 合法新邮箱，When 请求并校验开发验证码，Then 创建邮箱用户、设置 HttpOnly 会话并认领匿名项目。
2. Given 同一邮箱 60 秒内再次请求，When 请求验证码，Then 返回 429。
3. Given 生产环境未配置 SMTP，When 请求邮箱验证码，Then 返回 503 且响应不包含验证码。
4. Given 错误或过期验证码，When 校验，Then 拒绝登录且不创建会话。
5. Given 既有手机号数据库，When 新版本启动，Then 手机号用户、项目和会话仍可读取，并同时支持邮箱用户。
6. Given 邮箱账号已登录，When Web 打开登录页，Then 账号信息显示邮箱而不是空手机号。
7. Given 原有手机号 API，When 使用开发验证码登录，Then 原有行为保持通过。
