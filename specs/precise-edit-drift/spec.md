# 按 ID 精准修改与漂移检测

> 状态：已实现，等待产品验收  
> 日期：2026-11-04  
> 优先级：P0，创作安全

## 1. 目标

让 Agent 的待确认修改始终落到当前项目中真实存在的稳定实体上，并阻止
“提案生成后，用户又改了目标内容，确认时却被旧建议静默覆盖”。

这里不新增自由写库，不改变“Agent 只提议、用户确认后才写入”的边界。

## 2. 稳定目标

- 角色、地点、分集和镜头统一使用稳定 `targetId`。
- 镜头修改不能再只凭展示用镜号定位；镜号可以在增删镜头后变化。
- Agent 修改具体实体前先读取可编辑目标清单，拿到真实 ID。
- `propose_shot_edit` 和 `propose_entity_edit` 收到不存在的目标时必须拒绝。

## 3. 漂移检测

- 提案生成时记录目标字段的 `expectedText`。
- 用户点击确认时重新读取当前字段并比较。
- 目标不存在：拒绝写入，提示目标已不存在。
- 当前文本与 `expectedText` 不同：拒绝写入，提示目标已改动，需要重新读取。
- 文本完全一致：按稳定 ID 写入指定字段。
- 仅换行符或首尾空白不同不视为内容漂移；正文内部任何字符变化都视为漂移。

## 4. UI

- 待确认卡显示目标集数、镜号和场景，而不是只显示一个数字镜号。
- 卡片实时提示“目标已改动”或“目标已不存在”。
- 漂移时确认按钮不可用，不提供静默覆盖。
- 成功写入的提示只在该次确认确实完成后出现。
- 桌面右舱和手机底部抽屉共用同一状态判断。

## 5. 移动端

- Agent 返回的镜头卡携带 `targetId` 与 `expectedText`。
- 移动端已有的 `baseSnapshotId` 冲突保护继续保留。
- 按 ID 写入时同时校验字段文本，防止同一快照内的旧提案覆盖新输入。

## 6. 非目标

- 不根据自然语言相似度猜测“可能就是同一个实体”。
- 不允许用户强制覆盖漂移后的内容。
- 不自动合并两份修改。
- 不把实体名称当作稳定 ID。

## 7. 验收

1. 两个镜号相同的镜头按 `targetId` 只修改指定镜头。
2. 提案后正文被改动，确认不会写回，并返回可读的冲突原因。
3. 目标被删除后，确认不会写入。
4. 实体卡同样记录并校验字段原文。
5. `npm test`、TypeScript 与生产构建通过。
6. 桌面 1440 和手机 390 宽度真实页面无横向溢出、无浏览器错误。
