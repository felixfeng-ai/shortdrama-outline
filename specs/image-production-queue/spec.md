# 图像生产队列

## 目标

把批量图像生成从前端逐张请求、逐张限流、同步等待，升级为持久化生产队列。图像批次、暂停恢复、优先级、自动重试和统一额度必须共享同一套项目事实。

## P0

- 登录用户不再受“每账号 10 张 / 10 分钟”的图像硬限制。
- 一次批量提交只占用一次批次级请求限流。
- 上游 429、网络中断和 5xx 自动指数退避重试。
- 保留每日额度、全站成本熔断、预检和余额提示。
- 默认体验额度从 65 提高到能完成至少一集含图片样片的水平。

## P1

- 新增持久化图像批次 API。
- 服务端 Worker 从数据库领取图像任务并执行。
- 页面关闭后任务继续，重新打开可恢复进度。
- 批次进度、失败项和候选资产持久化。
- 失败项支持单张重试和整批失败重试。

## P2

- 上游模型并发由服务端配置，不暴露给用户。
- 批次显示队列位置和预计剩余时间。
- 支持暂停、恢复、取消和优先级。
- 人物定妆、地点场景图、镜头首帧和返修生成共用统一队列。

## 数据与状态

- `generation_batches` 增加媒体类型、优先级、并发和暂停状态。
- `generation_tasks` 保存批次 id、请求参数、重试次数、下次执行时间和额度预扣。
- 批次状态：`confirmed`、`running`、`completed`、`stopped`、`failed`。
- 任务状态：`queued`、`running`、`succeeded`、`failed`、`canceled`。

## 场景

### 批量提交

给定用户提交 100 个图像目标  
当创建图像批次时  
则 API 立即返回批次 id，任务进入服务端队列，页面关闭后继续执行。

### 上游限流

给定供应商返回 429  
当 Worker 执行任务时  
则任务按退避时间重新排队，超过最大次数后才标记失败。

### 暂停与恢复

给定批次正在排队或生成  
当用户暂停批次时  
则不再领取新任务；恢复后继续处理剩余任务，已完成结果不丢失。

### 余额不足

给定批次预计成本超过当前剩余额度  
当提交批次时  
则整批不创建任务，返回明确差额和预计成本。

### 管理账号

给定当前账号命中无限额度白名单  
当创建和执行批次时  
则跳过平台额度与短时限流，但继续记录真实任务和用量。

## 验收

- 选择 18 张或更多图片不再因账号 10 张短时限流逐项失败。
- 页面关闭再打开后仍能恢复批次进度。
- 服务重启后 queued 任务仍可继续领取。
- 上游瞬时 429 不要求用户逐张点击重试。
- 普通账号仍受日额度和全站熔断保护。
- 定妆、场景和首帧都通过同一批次 API。
- 桌面和 390px 手机可查看进度、暂停、恢复和重试失败项。
